# 1 용도와 파일

- 두 콘텐츠의 콘셉트 기획서 `2 전체 플로우`에 삽입하는 요약 순서도임.

# 2 입력과 구성

## 2.1 내용과 서식의 범위

- 내용 기준 시점: 2026-11-05, 본 작업의 이미지 삽입 직전 콘셉트 본문.
- 내용 입력: [Cave Super Ball 기획서 초안](<../../../03_기반 기획/콘셉트/Cave Super Ball 기획서 초안.md>)의 전체 플로우와 [Cave Action 콘셉트 기획서](<../../../03_기반 기획/콘셉트/Cave Action 콘셉트 기획서.md>)의 전체 플로우.
- 서식 입력: 사용자 제공 `탈놀음한바탕_플로우-페이지-2.drawio.xml`의 `페이지-2`. mxfile과 mxGraphModel 구조, 시작 캡슐, 둥근 사각형, 조건 마름모, 화살표와 맑은 고딕 및 색상 사용을 참고함.
- 서식 원본의 게임 내용은 사용하지 않음. 미정인 참가 등록, 준비 완료와 체험 종료 단계를 추가하지 않음.

- 체력 소진 `예`: 게임 종료 → 재시작 대기 → 게임 준비로 진행함.

- 공수 교대 때는 체력을 유지하며 새 게임에서만 초기화함. 소행성은 게임 준비의 보조 설명에 포함하고 개별 반응은 생략함.

# 3 제작과 검토

## 3.1 제작 방식

- Python의 ElementTree로 압축하지 않은 draw.io XML을 생성함. 도형, 텍스트와 연결선을 각각 mxCell로 저장하여 draw.io에서 개별 편집할 수 있는 형식으로 작성함.
- 저장된 XML의 도형, 라벨과 연결 좌표를 읽어 Pillow로 PNG를 렌더링함. 별도의 이미지 생성 모델은 사용하지 않음.
- 캔버스는 각각 840 × 800, 1120 × 1100이며 PNG는 각 변을 2배로 출력함. 글꼴은 Windows 맑은 고딕과 맑은 고딕 굵게를 사용함.
- 제작 코드는 `90_작업 공간/CaveBall 전체 플로우/플로우 제작.py`에 보관함. 코드 실행 시 작업 중 폴더에 출력하며 기존 편집 정본을 자동 덮어쓰지 않음. 이후 XML을 직접 편집한 경우 해당 XML을 정본으로 사용함.

## 3.2 검토 결과와 한계

- XML 두 개의 파싱, 고유 셀 ID, 연결 대상 존재, 도형 수와 연결선 수 및 모든 진행 도형의 연결 여부 확인함.
- PNG 두 개의 열기, 한글 라벨과 화살표 방향, 도형 안의 문구 배치 및 분기 경로를 직접 확인함. 첫 렌더에서 분기 라벨의 배경이 연결선 일부를 가리는 문제를 발견하여 배경을 투명하게 수정함.
- PNG는 저장된 XML에서 렌더링하므로 두 형식의 라벨과 좌표를 같은 입력으로 관리함. 작업 중 파일을 자산 위치로 옮긴 전후 SHA-256 일치를 확인함.
- 각 콘셉트의 H1 3개와 기존 본문을 유지하고 `2 전체 플로우` 아래에 HTML img로 삽입함. 기존에 제거한 본문의 기준 링크는 복원하지 않음.
- draw.io 앱에서 직접 열기와 해당 앱의 출력 모양은 미확인임. PNG는 draw.io의 내보내기가 아닌 XML 기반 별도 렌더 결과이며, 앱의 글꼴 처리와 둥근 모서리 표현에 미세한 차이가 있을 수 있음. 게임 실행 검증과 콘셉트 승인도 본 작업 범위에 포함하지 않음.
