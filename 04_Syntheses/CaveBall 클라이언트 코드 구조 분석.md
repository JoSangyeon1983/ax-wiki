> CaveBall은 콘텐츠 생명주기, 다면 디스플레이, 게임 상태, 자세 추정, 바닥 센서, 물리 공, 벽돌, 점수와 시각 효과를 런타임에 결합하는 Unity 콘텐츠임. 정적 코드 기준 핵심 놀이 흐름은 손으로 공에 진영 색을 부여하고, 바닥 접촉으로 공의 수평 진행 방향을 바꾸며, 같은 색 벽돌을 파괴해 반대편 점수를 올리는 구조임. 이 문서는 외부 클라이언트 소스를 읽기만 해 분석했으며 프리팹, 실제 설정 파일과 실행 결과는 확인하지 않았음.

## 1.2 분절 기준

코드를 파일 순서가 아니라 책임이 바뀌는 지점으로 분절함.

- **콘텐츠 생명주기**: 로드, 진입, 이탈과 언로드
- **표시 기반 시설**: 카메라, 디스플레이, 에지 블렌딩과 UI
- **게임 조정**: 초기화, 시작, 정지, 득점과 라운드 재설정
- **상호작용 입력**: 자세 추정 기반 손 접촉과 OSC 기반 바닥 접촉
- **도메인 규칙**: 공 상태, 색 일치, 좌표 변환과 물리 보정
- **피드백**: 벽돌, 점수판, 파티클, 카메라 흔들림과 실루엣
- **연결 미확인 요소**: 분석 범위 안에서 호출이 발견되지 않은 형식과 메서드

# 4. 실행 흐름

## 4.1 로드와 진입

1. `CaveBallContent`가 Addressable 키 `CaveballBG`로 배경 프리팹을 만들고 비활성화함 (`CaveBallContent.cs:13-25`).
2. `Setting/CaveballSetting.json`을 읽어 표시 장치와 게임 관리자를 초기화함 (`CaveBallContent.cs:28-50`).
3. 콘텐츠 진입 시 대화상자와 배경을 표시하고 UI 출력 적용, 게임 시작 순으로 호출함 (`CaveBallContent.cs:68-76`).
4. 콘텐츠 이탈 시 게임 정지, UI 출력 복원, 대화상자 숨김과 배경 비활성화를 수행함 (`CaveBallContent.cs:79-87`).

## 4.2 게임 시작과 라운드

1. 게임 관리자가 공, 벽돌, 효과 풀, 좌우 카메라 흔들림, 점수판과 두 입력 구성 요소를 준비함 (`CaveBallGameManager.cs:30-58`).
2. 게임 시작 시 배경음을 재생하고 벽돌, 점수와 공을 초기화한 뒤 자세 추정 세션과 바닥 센서 수신을 시작함 (`CaveBallGameManager.cs:62-75`).
3. 공은 흰색 상태에서 시작하며 기본 속도와 세 축의 최솟값을 반영한 방향으로 움직임 (`CaveBall.cs:37-52`).
4. 모든 벽돌이 사라지면 공을 멈추고 설정된 지연 뒤 라운드를 다시 초기화함 (`CaveBallGameManager.cs:130-134, 206-230`).

## 4.3 손 입력과 색 상태

- **입력 생성**:
	- 자세 추정 결과의 모든 처리 대상 사람을 순서대로 순회함
	- 왼손목은 빨간색, 오른손목은 파란색 입력으로 해석함
- **접촉 판정**:
	- 손목 신뢰도가 기준 이상일 때 손목을 전면 카메라 화면 좌표로 변환함
	- 손 접촉 사각형과 공 Collider의 화면 투영 사각형이 겹치면 색 적용을 요청함
- **상태 전이**:
	- 흰색 공만 빨간색 또는 파란색으로 바뀔 수 있음
	- 색이 붙은 공은 설정된 유지 시간이 지나면 흰색으로 돌아감
	- 색이 붙은 동안 다른 손 색으로 직접 덮어쓸 수 없음

근거는 `CaveBallMLInteraction.cs:143-225`, `CaveBall.cs:66-75, 109-125`, `Core/CaveBallRules.cs:19-23`임.

## 4.4 바닥 입력과 공 반사

- **센서 입력 처리**:
	- 지정한 센서 식별자의 OSC 점만 받음
	- 보정 최솟값과 최댓값으로 정규화하고 선택적으로 축을 뒤집음
	- 가까운 점은 기존 접촉에 합치고 오래 들어오지 않은 점은 제거함
- **반사 처리**:
	- 공이 경기장 바닥 높이에 충분히 가까운지 먼저 확인함
	- 접촉 사각형과 공의 바닥 투영 사각형이 겹치는 점 가운데 공 중심과 가장 가까운 점을 고름
	- 선택한 접촉점에서 공 중심으로 향하는 수평 방향을 반사 방향으로 사용하고, 설정된 재입력 대기 시간을 적용함

근거는 `CaveBallFloorInteraction.cs:84-176, 188-210`, `CaveBall.cs:77-107`임.

## 4.5 벽돌 파괴와 득점

- **파괴 조건**: 공과 벽돌의 색이 같을 때만 벽돌을 비활성화함 (`Core/CaveBallRules.cs:25-29`, `CaveBallBrick.cs:25-45`).
- **득점 방향**:
	- 빨간 벽돌을 파괴하면 파란 진영 점수를 올림
	- 파란 벽돌을 파괴하면 빨간 진영 점수를 올림
- **피드백**: 파괴된 벽돌 쪽 효과와 카메라 흔들림을 재생하고, 실제 득점 진영의 점수판을 갱신하고 흔듦 (`CaveBallGameManager.cs:93-128`, `CaveBallScoreboard.cs:40-50`).
- **라운드 경계**: 마지막 벽돌이 파괴된 뒤 재설정할 때 두 점수를 모두 초기화하므로 현재 구현의 점수는 한 라운드 안에서만 누적됨 (`CaveBallGameManager.cs:130-134, 219-230`).

# 5. 설정과 런타임 의존성

## 5.1 설정 체계

`CaveBallSetting`의 필드는 다음 묶음으로 나뉨. 클래스의 초기값은 기본값일 뿐이며 실제 실행값은 외부 JSON 확인이 필요함.

- **출력**: 전면, 좌측, 우측, 바닥과 바닥 블렌딩 디스플레이 번호
- **경기장**: 중심, 크기와 전면 상호작용 깊이
- **공과 라운드**: 기본 속도, 바닥 반사 가속, 최대 속도, 축별 최소 속도, 색 유지 시간과 재설정 지연
- **손 추적**: 좌표 반전, 최대 추적 인원, 손목 신뢰도, 접촉 반경과 입력 만료 시간
- **바닥 센서**: 센서 식별자, OSC 보정 범위, 축 반전, 접촉 반경, 높이 허용치, 유지 시간, 병합 거리와 재입력 대기 시간
- **피드백**: 벽돌 효과 풀, 카메라 흔들림과 점수판 표시값

근거는 `CaveBallSetting.cs:7-63`과 `CaveBallContent.cs:28-31`임.

# 6. 코드 기준 확인 사항

## 6.1 우선 확인

- **초기화 실패 전파가 약함**:
	- 설정 로드 결과가 비어 있는지 확인하지 않고 표시 장치 구성으로 넘김 (`CaveBallContent.cs:28-43`)
	- 게임 관리자 초기화의 반환값을 사용하지 않으므로 공을 찾지 못한 상태가 상위 생명주기로 전달되지 않음 (`CaveBallContent.cs:45-50`, `CaveBallGameManager.cs:30-39`)
	- 프리팹 또는 설정 누락 시험으로 실제 실패 양상을 확인해야 함
- **프리팹 이름과 레이어에 강하게 결합됨**:
	- 여러 구성 요소를 문자열 이름으로 찾아 누락 시 기능 일부가 조용히 빠지거나 경고만 남음
	- `UIEffect`와 `FloorDebug` 레이어가 없으면 각각 숫자 레이어를 대체값으로 사용하므로 프로젝트 레이어 배치와 충돌하는지 확인해야 함 (`CaveBallMLInteraction.cs:11-17`, `CaveBallSilhouetteView.cs:38-42`, `CaveBallFloorInteraction.cs:232-250`)
- **대표 사용자 선택기가 연결되지 않음**:
	- `PrimaryUserPoseSelector`는 화면 중심, 인물 크기와 이전 식별자를 이용한 선택 규칙을 가졌지만 분석 범위 안의 호출이 없음
	- 현재 상호작용은 처리된 사람 목록의 앞부분을 설정된 슬롯 수만큼 사용하므로 사람 배열 순서가 바뀔 때 손 효과의 사용자 대응이 안정적인지 실행 확인이 필요함 (`CaveBallMLInteraction.cs:158-180`, `PrimaryUserPoseSelector.cs:8-49`)

## 6.2 동작 경계 확인

- **최대 속도 보정 순서**:
	- 먼저 전체 속도를 최대 속도로 제한한 뒤 각 축을 최소 속도 이상으로 올림
	- 축 보정 뒤 전체 크기를 다시 제한하지 않으므로 결과 속도가 설정된 최대값을 조금 넘을 수 있는지 경계값 시험이 필요함 (`CaveBall.cs:128-146, 201-218`)
- **점수의 수명**:
	- 마지막 벽돌 뒤 라운드 재설정에서 점수가 초기화됨
	- 세션 누적 점수가 기획 의도라면 별도 누적 상태가 필요하고, 라운드 점수가 의도라면 현재 동작과 맞음 (`CaveBallGameManager.cs:219-230`)
- **구독 해제 경로**:
	- 정상 콘텐츠 이탈은 `StopGame`을 호출해 자세 추정 메시지 구독을 해제함
	- `CaveBallMLInteraction` 자체가 비활성화될 때는 손 효과만 숨기므로 이 구성 요소만 따로 끄는 운용이 있는지 확인해야 함 (`CaveBallContent.cs:79-87`, `CaveBallMLInteraction.cs:66-90, 374-377`)
- **시간 기준 혼용**:
	- 입력 만료, 반사 재입력과 라운드 재설정은 실제 시간 기준임
	- 벽돌 효과 풀 반환은 게임 시간 배율의 영향을 받으므로 일시 정지나 시간 배율 변경 시 효과 회수 시점이 달라질 수 있음 (`CaveBallEffectPool.cs:84-90`)
- **카메라 레이어 마스크 변경 범위**:
	- 실루엣 초기화는 같은 루트 아래 전면 카메라에 `UIEffect`를 넣고 다른 카메라에서는 뺌
	- 바닥 디버그도 같은 방식으로 바닥 카메라 외의 마스크에서 제외하므로 같은 레이어를 공유하는 다른 오브젝트가 의도치 않게 숨는지 확인해야 함 (`CaveBallSilhouetteView.cs:58-69`, `CaveBallFloorInteraction.cs:240-250`)
- **색 변경음 호출 범위**:
	- 상태 색을 적용할 때마다 효과음 호출이 함께 실행됨
	- 초기 흰색 설정, 라운드 재설정과 색 만료 뒤 흰색 복귀에도 소리가 필요한지 확인해야 함 (`CaveBall.cs:23-34, 109-125, 221-242`)
- **바닥 접촉 목록 크기**:
	- 들어온 점은 거리 기준으로 합치고 유지 시간이 지나면 제거하지만 별도 최대 개수는 없음
	- 센서가 한 프레임에 많은 분산 점을 보내는 조건에서 목록과 디버그 오브젝트 증가를 확인해야 함 (`CaveBallFloorInteraction.cs:84-135, 266-282`)
