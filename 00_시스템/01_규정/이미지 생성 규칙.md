# 1 목적과 기본 원칙

- **적용 범위**: GPT Image를 이용한 정보그래픽의 내용 분석, 구성 설계, 프롬프트 작성, 생성과 검수에 적용함.
- **렌더 문자열 우선 확정**: 이미지에 넣을 한국어 라벨과 지정 외 텍스트 금지를 먼저 명시하여 오탈자와 불필요한 텍스트의 발생을 줄이도록 함. 문자열 확정만으로 정확한 렌더링을 보장할 수 없으므로 생성 결과를 대조함. [공식 이미지 프롬프트 지침](<https://developers.openai.com/api/docs/guides/image-prompting>)의 정확한 문자열, 위치와 횟수 지정 및 결과 검수 방식 참고함.
- **분석과 설계 우선 수행**: [작성 규칙: 작성 순서](<작성 규칙.md#2-작성-순서>)와 [작성 규칙: 배열과 분류](<작성 규칙.md#41-배열과-분류>)를 함께 적용함. 공통 분석 절차를 마친 뒤 핵심 메시지, 표시할 정보, 렌더 문자열과 레이아웃을 정하고 프롬프트 작성함.

# 2 내용 분석

## 2.1 표시 정보 선택과 분류

- 원자료에서 개수, 분류, 단계나 목차를 새로 도출할 때는 [작성 규칙: 원자료 추출](<작성 규칙.md#22-원자료-추출>)을 먼저 완료함. 이미 확정된 구조를 사용할 때는 해당 구조를 바탕으로 아래 이미지 전용 분석 수행함.
- **핵심 메시지**: 구성 설계의 기준이 될 핵심 메시지 1문장 도출함. "X로 Y를 하는 Z" 구조 권장함. 실제 이미지의 전체 제목 표시 여부는 [이미지 생성 규칙: 레이아웃 선택](<#31-레이아웃-선택>)에서 별도로 결정함.
- **서사 구조**: 내용을 배경과 문제, 해법과 기술, 성과와 비전의 흐름으로 배열함.
- **정보 블록 분류**: 블록마다 프로세스(단계), 나열(고객, 가치), 대비(전과 후), 정량(수치) 유형 판정함.

## 2.2 렌더 문자열 확정

- **라벨 계층과 길이**: 블록별 헤더(2~8자 명사형)와 부연 캡션(20자 이내, 명사형 종결)의 2층 구조까지 허용함. 고밀도 구성에 고정 상한을 두지 않으며 모든 생성물을 [이미지 생성 규칙: 생성과 검수](<#5-생성과-검수>)에 따라 검수함. 문장형 캡션은 개수와 무관하게 금지함.
- **라벨과 연출 구분**: 라벨은 명사형으로 작성함. "웃는 노인", "창고형 약국 사진" 같은 장면 묘사는 렌더 문자열 목록에서 제외하고 [이미지 생성 규칙: 프롬프트 작성](<#4-프롬프트-작성>)의 영어 연출 서술에 배치함.
- **구두점과 기호**: 문자열에 포함할 구두점과 기호를 확정함. 라벨 끝 마침표와 마크다운 기호 제외함. 검수 시 제목 앞 "#" 등 의도하지 않은 기호의 출력 여부 확인함.
- **위치와 횟수**: 같은 문자열은 기본적으로 한 곳에만 배정함. 아이콘 안에 인접 라벨을 반복해야 하면 라벨 1회, 아이콘 1회처럼 위치와 횟수를 미리 배정함.
- **지정 외 텍스트**: 확정 목록에 없는 글자는 이미지에 추가하지 않도록 지시함.

# 3 구성 설계

## 3.1 레이아웃 선택

- **사용 조건**: 이미지의 사용 위치와 실제 표시 크기를 확인하고 화면비 정함. `6:4`는 `3:2`와 같은 비율임. 지정이 없는 경우의 실행 기본값은 [이미지 생성 규칙: 생성 경로와 실행 설정](<#51-생성-경로와-실행-설정>) 따름.
- **제목 표시**: 전체 상단 제목과 요소별 라벨을 구분하고 각각의 표시 여부 정함. 전체 제목을 제외하는 구성에서도 요소별 짧은 라벨은 배정 가능함.
- 서사 구조에 맞는 레이아웃 패턴 선택함. 격자형과 비격자형의 두 계열로 구분함.
- **계열 정의**: 격자형은 정보 블록을 채움 색이 있는 둥근 사각 패널로 정렬하는 구성임. 비격자형은 열린 캔버스에 요소를 자유 배치하는 구성임. 각각 문서 삽화와 홍보용 정보그래픽의 용도에 맞춰 선택함.
- **프롬프트 어휘**: `grid`, `aligned`, `panels`, `cards`는 격자 구성을 유도할 수 있음. 비격자형은 열린 캔버스와 자유 배치를 명시함. 특정 어휘만으로 배치가 보장되지는 않으므로 생성 후 실제 구성을 확인함. [공식 이미지 생성 지침: 한계](<https://developers.openai.com/api/docs/guides/image-generation#limitations>)의 정밀 배치 한계 참고함.

## 3.2 레이아웃 패턴과 장치

- **격자형 패턴**
  - 히어로 밴드와 하단 N패널: 스토리 강조와 섹션 요약이 함께 필요한 구성임.
  - 좌에서 우로 이어지는 플로우: 프로세스 중심 구성임.
  - 중앙 허브와 방사형: 하나의 플랫폼에 여러 요소가 연결되는 구성임.
- **비격자형 패턴**
  - 커넥터 스파인형: 세로 중심선의 노드와 연결 항목으로 구성하는 노선도 형식임.
  - 궤도 허브형: 중앙 엠블럼 둘레의 원형 사진 인셋과 곡선 연결선으로 구성함.
  - 히어로 지배 비대칭형: 중앙의 대형 실사와 크기가 다른 주변 정보 클러스터로 구성함.
- **비격자 공통 장치**
  - 항목 구분: 개별 카드 대신 가는 구분선(hairline) 사용함.
  - 섹션 제목: 리더 라인이 있는 pill 배지로 표시함.
  - 사진 인셋: 원형 사진을 영역 경계에 살짝 겹치게 배치함.
  - 배경: 중앙으로 좁아지는 화살촉형 등 유기적인 라운드 형상 사용함.

## 3.3 배치와 시각 요소

### 3.3.1 시각 어휘와 의미 배정

- **시각 어휘 배정**: 블록별로 실사 사진(감성, 현장), 3D 조형물(개념의 입체 표현), 사용자 인터페이스(UI, User Interface) 목업(제품), 아이콘(개념 나열), 차트(정량) 배정함. 각 이미지와 조형물이 표현할 대상과 의미 명시함.
- **선택과 혼합**: 실사와 3D 중 하나를 선택할지 함께 사용할지 정하고 각 요소의 역할 명시함. 여러 시각 어휘를 함께 사용할 때는 정보의 관계와 시선 흐름이 명확한지 확인함.
- **혼합 시 조화**: 배색, 광원 방향, 그림자와 상대 크기를 조정하여 한 구성 안에서 조화되도록 설계함. 같은 공간에 놓이는 요소는 시점과 원근의 일관성도 확인함.
- **텍스트가 포함되기 쉬운 소품**: 달력, 표지판, 차량과 포장 상자에 무관한 연도, 브랜드와 영문 문구가 생성될 수 있으므로 사용을 최소화하고 생성 후 확인함.

### 3.3.2 라벨과 시각 위계

- **라벨과 요소 연결**: 비격자형에서는 캡션이 어느 요소 밑에 붙는지 `directly beneath` 등으로 명시함. 연결선 위 단계 라벨은 2~4자의 자주 쓰는 단어로 짧게 작성함.
- **크기와 여백**: 라벨은 실제 표시 크기에서 읽히는 글자 크기와 대비로 배치하고 주변 여백 확보함. 짧은 문자열만으로 가독성이 확보된다고 판단하지 않으며 생성 후 실제 사용 크기로 확인함.
- **위계와 세부 묘사**: 핵심 이미지, 보조 이미지와 라벨의 중요도에 맞춰 크기와 강조 정도 정함. 질감과 장식의 세부 묘사가 라벨과 관계의 판독을 방해하지 않도록 조정함.

### 3.3.3 시선 흐름과 연결선

- **읽는 순서**: 좌에서 우로, 상단 서사에서 하단 근거로 이어지는 순서 등 내용에 맞는 시선 흐름 설계함. 요소의 배치와 크기, 여백으로 읽는 순서가 드러나도록 함.
- **관계와 방향**: 연결선마다 연결 대상과 관계, 방향 유무를 정함. 순서와 전달은 화살표, 방향 없는 연관은 일반 연결선으로 표시함. 단순 연관을 인과관계나 단계 진행으로 오해하게 하는 방향 표기 금지함.
- **연결 위치**: 선의 시작점과 끝점을 지정하고 라벨을 가리거나 불필요하게 교차하지 않도록 배치함. 의미가 없는 장식용 연결선 제외함.

## 3.4 정량 정보

- 수치의 정확성이 필요한 차트는 Pillow나 SVG(Scalable Vector Graphics)로 별도 제작하여 문서에 삽입함. 생성 이미지 안의 차트는 수치 없는 추상 도형으로 지시함.
- 수치를 생성 이미지에 넣어야 하면 차트와 분리된 배지형 라벨에 지표명과 값 표시함.
- 추상 도형을 포함한 차트를 배치할 때는 상승, 하강 등 추세 방향을 먼저 확정하고 프롬프트 지시와 검수의 기준으로 사용함.
- 검수 시 성과의 의미와 곡선 방향, 축 라벨과 값의 대응 여부 확인함.

## 3.5 시각 스타일 선택

- **기본 연출**: 사진 영역은 실사, 아이콘과 일러스트는 채움 색이 있는 풀컬러로 지시함. 단색 라인 아이콘 위주의 미니멀 스타일 지양함. `colorful filled icons`, `vibrant flat illustrations` 등의 표현 사용함.
- **배경과 조명**: 흰 배경, 부드러운 스튜디오 조명과 은은한 그림자 등은 용도에 맞춰 선택함. 배경의 장식이 정보 요소와 경쟁하지 않도록 함.
- **구도와 형태**: 아이소메트릭(등각 투영) 구도, 귀여운 조형, 기하학적 형태 등은 전달할 의미와 독자에 맞춰 선택함. 한 공간 안의 조형물은 선택한 구도에 맞춰 배치함.
- **색과 재질**: 무광 재질, 그라데이션 배색, 사실적 질감과 접촉부 음영 등은 강조할 특징에 맞춰 선택함. 시각 스타일별 연출을 모든 이미지의 필수 조건으로 동시에 적용하지 않음.

# 4 프롬프트 작성

- **전체 스타일 선언**: 용도, 품질 톤, 배색, 타이포와 레이아웃 계열을 첫 문단에 명시함. 비격자형은 `organic editorial composition`, `open canvas`, `NO boxed cards`, `NO uniform rectangular panels` 등으로 지시함. 격자를 유도할 수 있는 어휘의 혼용은 피함.
- **외형 표현과 실행 설정**: `C4D`, `Octane`, `Unreal Engine 5` 등의 이름은 현재 생성 경로에서 외형을 참고하는 표현으로 사용함. 해당 렌더러를 실제 실행하는 설정으로 취급하지 않음. `8K`, 초고화질, 프리미엄 등의 수식어 반복을 줄이고 구도, 소재, 배색과 조명으로 구체화함. 실제 출력 해상도는 지원 설정과 반환된 파일 사양으로 확인함.
- **연출과 렌더 문자열 분리**: 장면, 인물, 분위기와 위치 지시는 영어 산문으로 작성하고 한국어 렌더 문자열은 따옴표 안에 배치함. 연출 지시가 이미지 텍스트로 출력될 위험을 줄이기 위한 작성 기준임. 프롬프트 본문의 마크다운 문법 사용 금지함.
- **텍스트 통제 규칙**: 스타일 선언 직후 확정 문자열의 위치, 횟수와 철자를 명시함. 지정 외 텍스트, 실존 브랜드 로고, 상표와 워터마크 생성 금지함. 장식 요소와 사진의 텍스트는 제외하고 화면 목업 내부는 추상 도형만 허용함.
- **영역별 서술**: 구성 설계에 따라 영역별로 서술하고 라벨은 따옴표로 구분함.

# 5 생성과 검수

## 5.1 생성 경로와 실행 설정

- **경로 선택**: 별도 지정이 없으면 내장 `image_gen` 사용함. 사용자가 힉스필드 등 다른 생성 경로를 명시한 경우 해당 지정 적용함.
- **내장 도구 설정**: 구성 의도와 화면비를 프롬프트에 명시함. 별도 화면비 지정이 없으면 `16:9` 요청함. 현재 도구에 모델, 해상도와 품질의 직접 지정 인자가 없으므로 서비스가 제공하는 내장 모델 사용함. 특정 모델명을 저장소의 고정 기본값으로 지정하지 않으며 실제 출력 규격은 반환 파일로 확인함.
- **내장 모델 확인**: [공식 내장 이미지 생성 안내](<https://learn.chatgpt.com/docs/image-generation#generate-or-edit-an-image>)는 `gpt-image-2` 사용을 설명함. 확인일은 2026-10-12이며 해당 안내 값과 호출 반환으로 확인한 실제 모델 구분함. 신규 이미지 모델 출시 직후 내장 경로가 자동으로 최신 모델로 전환되는 정책과 시점은 미확인임.
- **힉스필드 별도 지정 시 설정**: `gpt_image_2` 사용함. 화면비는 별도 지정이 없으면 `16:9` 사용함. 다른 화면비는 해당 모델이 지원하는 같은 비율의 값으로 전달함. 1차 생성은 `resolution: 1k`, `quality: medium`으로 지정함. 사용자가 요청할 때만 `resolution: 2k`, `quality: high`로 생성함. 실행 전 해당 모델의 지원 값 확인함.
- **실행 기록**: 위 값은 이 저장소의 실행 설정임. 지원 값이나 사용자 기본값이 변경되면 규칙 갱신함. 생성 기록에 실제 도구, 확인 가능한 모델, 전달한 설정과 반환된 출력 사양을 남김. 호출 반환에서 모델을 확인할 수 없으면 미확인으로 기록하고 공식 안내를 참고한 경우 출처와 확인일 함께 기록함.

## 5.2 검수 절차

1. **직접 대조**: 생성물을 내려받아 확정 라벨의 철자, 누락, 판독 가능 여부, 위치와 횟수 대조함. 미세 텍스트는 원본을 확대하여 확인함. 실존 브랜드와 문자 없는 로고는 이미지를 직접 확인함. 작성자의 기대 편향을 줄이기 위해 다음 검수도 함께 수행함.
2. **블라인드 전사**: 정답 라벨을 주지 않은 별도 컨텍스트의 서브에이전트에게 모든 텍스트를 보이는 철자 그대로 전사하게 함. 오탈자를 임의로 수정하지 않고 판독 불가 영역과 애매한 글자의 위치 기록함. 차트의 추세 방향과 축 라벨도 기록함. 이미지가 여럿이면 이미지별로 전사 작업을 배정하고 허용되는 동시 실행 범위에서 병렬 수행함.
3. **기계 대조**: 전사본과 확정 목록의 문자열, 누락 및 배정 횟수의 미달과 초과 대조함. 목록 외 텍스트, 브랜드명과 의도하지 않은 단어 반복 검출함. 전사된 차트 방향을 설계 기준과 대조하고 판독 불가 영역과 애매한 글자도 수집함. 그래픽 형태의 로고는 직접 시각 검수 결과와 함께 판단함.

전사 결과도 오독 가능성이 있으므로 불확실한 영역은 원본 확대와 직접 대조로 재확인함. 판독 모델의 한계는 [이미지 생성 규칙: 공식 이미지 판독 지침의 한계](<#521-공식-이미지-판독-지침의-한계>) 참고함.

### 5.2.1 공식 이미지 판독 지침의 한계

[공식 이미지 판독 지침: 한계](<https://developers.openai.com/api/docs/guides/images-vision#limitations>)의 내용을 한국어 개조식으로 번역 요약함. 일반적인 이미지 판독 모델에 관한 설명이며, 원문 확인일은 2026-10-08임.

#### 1) 문자와 그래프

- **비라틴 문자**: 한국어와 일본어 등 비라틴 문자가 있는 이미지에서 최적의 성능을 내지 못할 수 있음.
- **작은 글자**: 이미지 안의 글자를 확대하면 가독성 개선 가능함. 지원되는 경우 `"detail": "original"`도 판독 성능에 도움이 될 수 있음.
- **회전**: 회전하거나 거꾸로 된 글자와 이미지를 잘못 해석할 수 있음.
- **시각 요소**: 색상이나 실선, 파선, 점선 등의 스타일 차이가 있는 그래프와 텍스트를 이해하는 데 어려움이 있을 수 있음.

#### 2) 위치, 형태와 개수

- **공간 추론**: 체스 말의 배치 식별처럼 정확한 공간 위치 판단이 필요한 작업에 어려움이 있음.
- **이미지 형태**: 파노라마와 어안 이미지를 이해하는 데 어려움이 있음.
- **개수 계산**: 이미지 속 객체의 개수를 근사값으로 제시할 수 있음.

#### 3) 정확도와 입력 처리

- **정확도**: 상황에 따라 잘못된 설명이나 캡션을 생성할 수 있음.
- **메타데이터와 크기 조정**: 원본 파일명과 메타데이터는 처리하지 않음. `original` 설정에서도 분석 전에 이미지 크기가 조정될 수 있으므로 원문의 모델별 크기 처리 규정 확인 필요함.
- **전문 의료 이미지**: 컴퓨터 단층촬영 같은 전문 의료 영상의 해석에 적합하지 않으며 의료 조언에 사용해서는 안 됨.
- **캡차**: 안전상의 이유로 시스템에서 캡차 제출을 차단함.

## 5.3 재생성 기준

아래 결함 중 하나라도 있으면 재생성함.

- 지정 라벨의 오탈자, 누락 또는 판독 불가임.
- 지정 문자열의 배정 횟수 미달, 초과 또는 지정 위치와 다른 배치임.
- 목록 외 판독 가능한 텍스트임. 수치, 기관명과 연도도 포함함.
- 실존 브랜드명, 상표 또는 문자 없는 로고의 노출임.
- 확정 방향과 어긋난 차트 추세임.

지정 외 영역의 판독 불가한 미세 유사 한글은 실제 사용 크기에서 보이지 않으면 허용하되 기록에 남김. 지정 라벨의 애매한 글자는 원본에서도 판독이 불확실하면 결함으로 처리하고 재생성 또는 라벨 단순화를 검토함.

## 5.4 최종 이미지와 통합 작업 기록

### 5.4.1 관리 단위와 파일 생성

- 콘텐츠별 최종 이미지 여러 장과 통합 작업 기록 1개를 상시 관리함. 기존 리소스 설명 문서가 있으면 그 문서에 기록을 통합하고, 위치는 사용자 지정과 [문서 형식: `06_자산`](<문서 형식.md#8-자산>) 따름.
- 프롬프트, 설정, 라벨, 블라인드 전사와 검수 결과는 통합 Markdown에 기록함. 단계별 TXT와 JSON을 기본 산출물로 추가하지 않음. 기계 판독이 필요하면 같은 문서 안의 코드 블록에 구조화된 데이터 저장함.
- 재사용할 최종 제작 이미지는 `06_자산`, 독립 사용과 전달을 목적으로 별도 만든 이미지는 `08_산출물`에서 관리함. 파일별 정본과 파생 출력의 관계를 기록하며 같은 정본을 두 위치에 중복 관리하지 않음. 수정 시 실제 정본 위치에 반영하고 같은 내용의 작업 공간 복사본은 해시 대조 후 정리함.
- 미리보기와 확대 확인은 화면에서 수행함. 별도 비교판이나 표시 크기 검수 파일은 사용자가 해당 결과물을 요청하거나 화면 확인만으로 검수하기 어려운 경우에만 저장하고, 필요 이유를 기록함.
- 생성 시도는 번호와 상태로 식별함. 검수 전 작업물에 `최종` 명칭을 사용하지 않으며 수정 전 원본은 작업별로 1개만 보존함.

### 5.4.2 생성, 검수와 보관 순서

1. 통합 작업 기록에 생성 또는 수정 요청, 입력 자료와 실제 프롬프트 추가함.
2. 작업 공간의 콘텐츠별 이미지 폴더 아래 `작업 중/날짜 대상 변경내용` 폴더에서 작업함. 원본과 각 생성 시도의 PNG를 해당 작업 폴더에 모음.
3. [이미지 생성 규칙: 검수 절차](<#52-검수-절차>)의 직접 대조, 블라인드 전사와 기계 대조 수행함. 재시도는 발견한 문제, 변경 내용과 채택 여부 기록함.
4. 검수 통과한 이미지를 최종 위치에 반영하고 통합 기록의 현재 파일 정보와 검수 결과 갱신함. 파일 경로, 해시와 문서 삽입 링크 대조 후 중복 최종본 정리함.
5. 완료한 작업의 중간 자료는 작업별 폴더째 `99_보관소/종료 작업`에 보관함. 통합 기록에는 보관 작업 ID와 경로 문자열만 남기고 아카이브 내부로 연결하는 링크는 만들지 않음.

### 5.4.3 기록 내용과 재검증

- 통합 기록에 사용 위치, 입력 근거, 실제 프롬프트와 도구 설정, 확인 가능한 모델, 출력 규격과 해시, 지정 라벨 및 최종 블라인드 전사, 직접 검수와 기계 대조 결과 기록함.
- 현재 사용본과 최초 생성 비교, 미채택 시도를 구분함. 이미지 정리만 수행한 경우 기존 시각 검수의 전사와 실제 수행한 파일 검증을 구분하고 새로운 시각 검수를 수행한 것으로 기록하지 않음.
- 구조화된 재검증 데이터는 `<!-- image-work-record:start -->`와 `<!-- image-work-record:end -->` 사이의 JSON 코드 블록에 저장함. 실제 프롬프트는 `<!-- image-prompt:식별자 -->` 다음의 `text` 코드 블록으로 보존함.
- [이미지 통합 기록 검증 도구](<../03_도구/image_record_check.py>)는 같은 Markdown에서 최종 이미지 정보, 라벨과 전사, 프롬프트 및 문서 경로를 읽음. 도구 출력은 표준 출력으로 확인하고 별도 결과 파일을 기본 생성하지 않음. 이 도구는 기록된 문자열과 파일을 대조하며 직접 시각 검수와 블라인드 전사를 대체하지 않음.
- 아래 명령은 위키 루트에서 실행하며 경로를 실제 통합 기록으로 대체함. 로컬 보관 파일 대조가 필요하면 `--archive` 추가함.

```powershell
python 00_시스템/03_도구/image_record_check.py "90_작업 공간/콘텐츠/이미지/이미지 작업 기록.md"
```
