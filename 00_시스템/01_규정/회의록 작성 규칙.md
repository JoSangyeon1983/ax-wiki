# 1 처리 원칙

- 사용자 제공 클로바 노트 TXT와 수기 녹취록 TXT를 전체 대조하여 녹취록 완성본을 작성한 뒤 회의록으로 정리함.
- 클로바 노트의 STT(Speech-to-Text, 음성의 텍스트 변환)는 발언 순서와 누락 확인에, 수기 녹취록은 용어와 문맥 교정에 활용함. 어느 한쪽을 일괄 우선하지 않고 발언 단위로 판단함.
- 녹취록 완성본은 두 TXT의 대조 편집본임. 원음 미제공 시 음성을 직접 확인한 녹취록으로 표시하지 않으며, 대조 작업의 완료와 미확인 내용의 해소를 구분함.
- 녹취록은 발언 순서와 의미를 보존하고, 회의록은 논의, 결정, 후속 작업과 미결 사항을 구분함. 두 자료에 없는 발언과 합의 생성 금지.
- 문서 작성에 사용할 기본 참고자료는 정리와 검증을 마친 회의록임. 원본 TXT, 녹취록 완성본과 대조표는 작업 공간의 교정과 검증 자료로 보존함.

# 2 파일 저장

## 2.1 회의 식별과 원본 보존

- 회의 식별명은 `YYYY-MM-DD 회의명`으로 통일함. 날짜가 확인되지 않으면 `일자미확인 회의명` 사용, 수신일을 회의일로 대체하지 않음. 같은 이름의 다른 회의는 식별용 접미사로 구분함.
- 전달받은 TXT는 작업 폴더의 `원문` 하위에 원본 그대로 저장함. 실제 원본 파일명을 유지하고, 이름 충돌로 변경 시 원본 이름과 보관 이름의 대응 기록함.
- 두 파일의 열기 가능 여부, 문자 인코딩, 동일 회의 여부와 포함 구간을 확인하고 작업 공간에 보존함. 대조는 사용자 제공 원본 TXT를 직접 읽어 수행함.
- 원본의 오탈자, 시각과 발언자 표기 수정 금지. UTF-8 변환이나 줄 번호 부여가 필요하면 작업 공간에 작업용 사본을 만들고 원본 위치와 대응시킴.

## 2.2 저장 경로와 문서 종류

아래 `회의 식별명`은 실제 회의 이름으로 치환함. 경로는 위키 루트 기준임.

| 파일 | 저장 경로 | 문서 종류와 역할 |
|---|---|---|
| 원본 TXT 2개 | `90_작업 공간/회의록/회의 식별명/원문/` | 사용자 제공 원자료, 원본 파일명 유지 |
| 녹취록 완성본 | `90_작업 공간/회의록/회의 식별명/회의 식별명 녹취록.md` | `reference`, 사용자 제공 발언을 대조 편집한 검증용 자료 |
| 대조표와 원자료 정보 | `90_작업 공간/회의록/회의 식별명/회의 식별명 대조표.md` | `system`, 원본 보존과 대조 및 교정 작업의 기록 |
| 회의록 초안 | `90_작업 공간/회의록/회의 식별명/회의 식별명 회의록.md` | `reference`, 정식 반영 전 검토 문서 |
| 정식 회의록 | `01_프로젝트/회의 및 검토/회의 식별명 회의록.md` | `reference`, 이후 문서 작성에 활용할 회의 내용의 기록 |

- 대조표에 원자료 정보, 최초 추출, 원문 대응, 교정 판단과 검증 기록을 함께 관리함. 편집과 검증의 작업 기록이므로 `type: system`과 공통 프론트매터 적용함.
- 녹취록 완성본과 회의록 초안은 `type: reference`, `target_folder: 01_프로젝트`로 작성함. 녹취록은 작업 공간에 보존하고, 이 절차에서 정식 반영하는 문서는 회의록임.
- TXT에는 프론트매터를 삽입하지 않음. 작업 기록과 결과물 Markdown은 [문서 형식](<문서 형식.md>)의 해당 문서 종류 규정 적용함.
- 기존 이관 회의록과 새로 작성한 정식 회의록은 모두 `01_프로젝트/회의 및 검토`에서 관리함.
- 여러 회의와 참고자료의 비교 분석 중 미채택 해석과 적용 제안은 `90_작업 공간`, 참고용 분석은 `05_참고 자료/분석 자료`에서 관리함. 명시적인 채택 결정이 있는 내용만 적용 범위와 함께 `02_기획 근거`에 정리함. 한 회의의 발언을 교정하고 정리하는 작업만으로 기획 근거로 분류하지 않음.

## 2.3 출처 연결

- 대조표의 원자료 정보에 두 TXT의 원본 이름, 작성 방식, 작성자 정보의 확인 여부, 회의 정보, 보관 위치, 인코딩과 포함 구간 기록함. 원본 보존 확인을 위해 파일별 SHA-256 해시도 기록함.
- 녹취록과 회의록의 `sources`에는 직접 사용한 사용자 제공 원자료를 자료 종류, 원본 파일명과 회의 식별명으로 기록함. 음성이나 참석자 확인 및 회의 후 보충 자료를 사용한 경우 실제 사용 자료도 추가함. 원자료가 작업 공간에 보관되어 있다는 이유로 Codex가 작성한 작업물과 같은 출처로 취급하지 않음.
- 작업 공간의 녹취록 완성본과 대조표는 편집과 검증에 사용함. 회의 중 발언의 직접 출처는 사용자 제공 원본 TXT와 실제 확인한 음성 자료이며, 참석자 확인과 회의 후 보충은 구분하여 기록함. 작업물의 표현만으로 발언의 검증 완료 처리 금지.
- 정식 회의록에 원본 파일 정보, 보관 위치, 검증 범위와 필요한 원문 위치 기록함. 작업 공간 파일의 링크를 제공할 때는 교정과 검증 자료임을 표시함.
- 의미가 달라지는 주요 교정, 내용 충돌과 미확인 사항은 녹취록에 남기고, 회의록에 포함되거나 그 내용에 영향을 주는 항목은 정식 회의록에도 기록함. 회의록 자체에서 원본과 판단 근거를 추적할 수 있게 함.

`sources`의 기록 형식 예시임. 실제 제공된 자료의 이름과 회의 정보로 치환함.

```yaml
sources:
  - "사용자 제공 클로바 노트 TXT: 원본 파일명, 회의 식별명."
  - "사용자 제공 수기 녹취록 TXT: 원본 파일명, 회의 식별명."
```

# 3 두 TXT의 대조

## 3.1 전체 읽기와 발언 대응

1. 두 파일을 처음부터 끝까지 읽고 시작과 끝의 발언, 시각 범위와 중간 누락 구간 기록함. 시각이 없으면 실제 줄 번호와 문단 위치 사용함.
2. 클로바 노트는 발언자, 행동, 주장과 상태가 바뀌는 단위로 추출하고 `C0001` 형식의 ID(Identifier, 식별자) 부여함. 수기 녹취록도 기록 단위별로 `H0001` 형식의 ID 부여함. 최초 추출표 저장 후 내용 분류함.
3. 공통 용어, 논의 대상, 질문과 응답, 수치와 발언 전후 맥락으로 대응 구간 연결함. 한 문장씩 강제 대응하지 않고 일대다, 다대일 대응 허용함. 반복 발언은 실제 구간이 다른지 확인함.
4. 대응되는 발언 묶음마다 `T0001` 형식의 완성본 ID 부여함. 분할과 병합 시 기존 ID와 변경 관계 기록함. 시각과 줄 번호를 자료별로 유지하고 없는 위치 정보 생성 금지.

## 3.2 대조표 기록

| 완성본 ID | 클로바 ID와 원문 위치 | 수기 ID와 원문 위치 | 차이와 양쪽 원문 | 채택 표현 또는 보류 내용 | 판단 근거와 상태 | 완성본 반영 위치 |
|---|---|---|---|---|---|---|
| 실제 ID | 시각과 줄 범위 | 줄 범위 또는 해당 기록 없음 | 실제 표현과 누락 여부 | 교정, 보충 또는 후보 병기 | 일치, 교정, 단독 기록, 충돌, 미확인 등 | 실제 발언 ID와 절 |

- 양쪽 원문은 판단에 필요한 구간을 보존하고, 최종 문장만 기록하여 교정 전 내용을 잃는 방식 금지.
- 양쪽의 모든 추출 단위는 완성본 발언에 대응하거나 제외 사유를 가짐. 발언 내용의 누락과 작업 중 미처리 항목 구분함.
- 단순 맞춤법과 문장부호 교정은 처리 원칙으로 묶어 기록 가능함. 인명, 기관명, 수치, 일정, 담당, 부정 표현과 결정 상태의 교정은 개별 기록함.

## 3.3 일치와 한쪽에만 있는 내용

| 대조 결과 | 처리 기준 |
|---|---|
| 의미 일치 | 발언 순서와 의미를 보존하여 읽기 쉬운 표현으로 정리함 |
| 클로바에만 존재 | 수기에서 빠진 내용일 수 있으므로 자동 삭제하지 않음. 문맥이 연결되면 발언에 반영하고 클로바 단독 기록임을 대조표에 남김. 의미가 불분명한 부분은 미확인 표시함 |
| 수기에만 존재 | 녹취 누락인지 작성자의 요약이나 메모인지 구분함. 발언 기록으로 확인되면 해당 맥락에 보충하되 정확한 시각을 만들지 않음. 요약이나 메모는 `[수기 보충: 내용]`으로 표시하고 실제 발언처럼 재구성하지 않음 |
| 반복, 말더듬과 비내용 잡음 | 의미 없는 중복과 잡음만 정리하고 제외 사유 기록함. 강조, 번복, 부정과 의견 차이를 나타내는 반복은 보존함 |

## 3.4 표현 차이와 내용 충돌

| 차이 유형 | 처리 기준 |
|---|---|
| STT의 명백한 오탈자 | 수기의 해당 구간과 회의 안의 다른 명시적 표기를 대조하여 교정함. 근거가 없는 전문 용어와 고유 명칭은 후보만 기록함 |
| 수치, 날짜, 담당, 발언 의미의 충돌 | 어느 한쪽을 임의 채택하거나 절충값을 만들지 않음. 양쪽 표현과 위치를 보존하고 `[내용 미확인]` 표시함 |
| 부정, 조건, 제안과 합의 표현의 차이 | 문맥상 자연스럽다는 이유만으로 교정하지 않음. 책임과 결정 상태에 영향을 주므로 명시적 근거가 없으면 충돌로 남김 |
| 앞뒤 발언의 수정과 번복 | 변경 과정 보존함. 최종 결정의 판정은 [회의록 작성 규칙: 결정 사항](<#521-결정-사항>) 기준 적용함. 마지막 발언이라는 이유만으로 최종 합의 처리 금지 |

- 불일치는 해당 구간부터 확인하고, 해소되지 않은 항목만 원본 후보와 함께 사용자에게 확인 요청함. 답이 필요한 부분은 미확인으로 유지하면서 나머지 대조와 회의록 정리 계속함.
- 원음이 제공되어 실제로 확인한 경우 해당 시각과 확인 결과 기록함. 원음 미제공이나 확인 불가만으로 전체 작업 중단 금지.
- 외부 자료, 기존 기획서와 일반 지식으로 회의에서 하지 않은 발언을 채워 넣는 행위 금지. 별도 해석이 필요하면 회의 발언과 분리함.

# 4 녹취록 완성본 작성

## 4.1 발언과 표기

- 본문은 회의 진행 순서대로 작성함. 회의록처럼 주제별 요약으로 대체하지 않음. 발언의 주체, 대상, 조건, 수치, 단위, 부정, 정정과 의견 차이 보존함.
- 발언별 완성본 ID, 원문에 있는 시각과 확인된 발언자 표기함. 예: `T0001 | 00:03:12 | 발언자 A`. 시각이 없으면 `시각 미확인`으로 표시함.
- 각 발언의 원본 파일, 시각과 줄 범위를 발언 옆 또는 교정 절의 대응표에 기록함. 작업용 추출 ID와 실제 원문 위치를 함께 기록함.
- 발언자는 자기소개, 명시적 호명과 대응되는 수기 기록으로 확인함. 직무와 발언 내용만으로 이름 추정 금지. 확인되지 않은 이름은 원문의 발언자 번호를 유지하거나 `발언자 미확인` 사용함.
- 발언 내용은 원문의 의미를 보존한 대조 편집문으로 작성함. 개조식 종결로 일괄 바꾸지 않음. 수기 메모와 편집자의 설명은 발언 밖에 구분하여 표시함.

## 4.2 문서 구성과 검토 상태

- 기본 구성: `자료 정보`, `녹취`, `교정과 미확인 사항`. 녹취의 세부 절은 실제 논의 흐름에 따라 구성하고 구간 수를 미리 정하지 않음.
- 자료 정보에 입력 TXT 2개의 연결, 포함 범위, 작성 방식과 원음 대조 여부 기록함. 제공 자료에서 확인하지 못한 회의 장소, 참석자와 회의 시간은 `미확인`으로 표시함. 추가 확인을 수행한 경우 그 자료, 방법과 범위도 기록함.
- 교정과 미확인 사항에 발언 ID, 양쪽 원문 위치, 의미에 영향을 주는 수정 전후 표현과 근거 기록함. 확인이 필요한 인명, 수치, 담당과 결정 상태는 빠짐없이 남김.
- 녹취록과 회의록의 `source_check`는 기존 메타데이터 값을 사용하고 [회의록 작성 규칙: 확인 방법과 검증 범위](<#612-확인-방법과-검증-범위>)에 따라 실제 확인 방법, 사용 자료, 대조 범위와 남은 한계를 기록함.

# 5 회의록 정리

## 5.1 정보 분류

### 5.1.1 회의 정보와 구성

- 기본 구성은 `회의 정보`, `주제별 논의`, `결정 사항`, `후속 작업`, `미결 사항 및 확인 필요 사항`으로 함. 실제 기록이 없는 절은 생략하거나 확인된 사항이 없음을 표시함.
- 회의 정보에는 일자와 시작 및 종료 시각, 장소 또는 진행 방식, 참석자와 역할, 회의 목적 또는 안건 기록함.
- 회의 정보는 제공 자료에서 확인한 값만 기록함. 확인되지 않거나 서로 다른 값은 `미확인`으로 표시하고 근거와 확인 방법을 남김. 진행 시간만으로 시작과 종료 시각을 만들거나 참석자의 직책만으로 해당 사안의 승인 권한을 추정하지 않음.

### 5.1.2 논의 정리와 발언 대응

- 녹취록 완성본 작성 후 발언 ID별로 회의록의 해당 항목 또는 제외 사유를 대조표에 추가함. 전체 추출 단위의 대응은 [회의록 작성 규칙: 대조표 기록](<#32-대조표-기록>) 기준 유지함.
- 연속된 잡담과 단순 반복은 원문 발언 ID 범위로 묶고 공통 제외 사유 사용 가능함. 의미가 있는 반복의 보존은 [회의록 작성 규칙: 일치와 한쪽에만 있는 내용](<#33-일치와-한쪽에만-있는-내용>) 기준 적용함.
- 주제별 논의는 실제 발언에서 도출한 주제로 묶고 쟁점, 제안, 반대 의견과 조건 보존함. 안건별 핵심과 결과를 먼저 제시하고 필요한 논의 경위를 뒤에 배치함.
- 상세 설명과 근거의 중복은 줄이고 공통 근거 위치를 참조함. 안건 요약, 결정 목록과 후속 작업 표에서 이해와 실행에 필요한 핵심 정보의 재표기는 허용함.

### 5.1.3 수기와 회의 후 보충

- TXT에 존재하는 발언의 교정과 TXT에 없는 내용의 추가를 구분함. 한쪽 TXT에만 있는 기록과 수기 메모의 처리는 [회의록 작성 규칙: 일치와 한쪽에만 있는 내용](<#33-일치와-한쪽에만-있는-내용>) 기준 적용함.
- 추가 내용에는 제공자, 전달일, 자료명과 위치 및 확인 상태를 기록함. 추가 자료에 근거가 없는 내용을 실제 발언으로 재구성하지 않음.
- 회의 후 전달된 설명은 `회의 후 보충`, 이후 변경 사항은 `회의 후 변경`으로 회의 중 발언과 구분함. 회의 중 결정과 이후 변경의 내용 및 확인된 적용 시점을 구분하고, 사후 설명만으로 녹음된 발언이나 회의 당시 합의를 확정하지 않음.

## 5.2 결정과 후속 작업 판정

### 5.2.1 결정 사항

- 결정 사항은 명시적인 합의 또는 해당 사안에 대한 권한 있는 승인으로 확인된 내용만 기록함. 제안, 검토 요청, 질문, 개인 의견과 응답 없는 발언을 합의나 결정으로 바꾸지 않음.
- 발언자의 해당 사안에 대한 승인 권한이 확인되지 않으면 기관의 승인으로 처리하지 않음. 발언자의 의견과 권한의 확인 상태를 구분하여 기록함.
- 조건부 합의와 승인에는 조건을 함께 기록함. 반대 의견과 부정 표현을 삭제하여 합의 범위를 넓히지 않음.
- 최종 결정의 `근거 위치`와 `결정 이유`를 구분함. 근거 위치는 실제 발언과 승인 기록의 위치로 표시하고, 결정 이유는 실제로 언급된 경우에만 기록함.
- 계획 변경 전후는 최종 결정의 의미, 조건이나 책임에 영향을 주는 변경을 중심으로 기록함. 상세 변경 과정은 녹취록과 대조표에서 추적함.

### 5.2.2 후속 작업

- 후속 작업은 `작업`, `담당`, `기한`, `조건`, `배정 또는 수행 확약 근거`로 정리함. 근거에는 권한 있는 업무 배정인지 담당자의 수행 확약인지 구분하여 표시함.
- 권한 있는 업무 배정은 담당자의 별도 확약이 없어도 배정된 작업으로 기록함. 배정 사실과 담당자의 수락 또는 확약 여부를 혼동하지 않음.
- 담당자의 수행 확약은 후속 작업의 근거로 기록하며 그 자체를 회의 전체의 합의로 간주하지 않음.
- 담당과 기한이 정해지지 않으면 `미정`, 배정이나 확약의 의미 또는 표현이 불분명하면 `미확인`으로 표시함. 직무나 관행으로 담당과 기한을 임의 배정하지 않음.

### 5.2.3 미결 사항 및 확인 필요 사항

- 설계나 결정이 남은 `미정`과 기록의 내용이 불분명한 `미확인`을 구분함. 요약 과정에서 확인 상태를 높이지 않음.
- 항목별 내용, 근거 위치와 현재 상태 기록함. 확인 담당과 기한이 정해진 경우 해당 값도 기록함.
- 결정 여부, 조건, 담당, 기한과 수치 등 중요한 미확인 항목은 해당 회의록 항목과 목록 또는 표에서 명확히 표시하고 확정 정보로 사용하지 않음.
- 회의록에 포함된 내용이나 그 판정에 영향을 주는 불확실성은 유지함. 제외된 발언의 미확인 사항은 대조표에서 관리하며 회의록의 내용에 영향이 없으면 회의록에 옮기지 않아도 됨.

## 5.3 근거 연결

- 주요 논의, 결정, 조건, 수치와 후속 작업에 대응하는 원본 파일의 위치와 녹취록 발언 ID를 연결함. 줄 번호는 원본 파일별 첫 행을 `1`로 시작하여 빈 행을 포함해 계산함. 시각과 작업용 사본의 원문 대응은 앞 장의 기준 적용함.
- 녹취록과 대조표의 링크는 교정과 검증 자료의 위치 안내로 사용함. 직접 출처와 검증 자료의 구분은 [회의록 작성 규칙: 출처 연결](<#23-출처-연결>) 기준 적용함.
- 이후 기획서 작성 시 정식 회의록의 확인 가능한 결정 사항과 해당 작업의 적용 범위만 사용함. 제안이나 의견을 모두 확정 기획 근거로 취급하지 않음. 원본 TXT와 작업용 녹취록 확인은 회의록의 의미, 발언과 교정 결과를 재검증할 필요가 있을 때 수행함.
- 원자료에서 주요 논의, 결정, 조건, 수치 또는 후속 작업에 영향을 주는 누락이나 오류를 발견한 경우 회의록을 먼저 교정하고 검증함. 그 내용에 영향이 없는 새 정보를 발견했다는 이유만으로 회의록을 확장하지 않음.
- 의미에 영향을 주는 교정은 연결된 회의록 항목과 후속 문서의 영향 범위도 점검함. 이후 문서의 근거는 필요한 교정과 검증을 반영한 정식 회의록에서 확인함.

# 6 검증과 반영

## 6.1 내용 검증

### 6.1.1 처리 범위와 필수 검증 항목

1. 두 TXT의 전체 범위와 추출 단위가 대조표에 대응하는지 확인함. 반영, 개별 또는 공통 제외 사유, 미처리 구간을 구분하여 전체 원자료의 처리 여부 추적함.
2. 회의록의 내용과 중요한 교정 및 보충의 근거를 실제 원자료 구간과 대조함. 의미, 발언 순서, 발언자와 위치 정보의 보존 여부 확인함.
3. 결정과 승인 근거, 조건, 반대 의견, 부정 표현, 담당, 기한, 수치와 단위를 필수 검증 항목으로 점검함. 판정은 [회의록 작성 규칙: 결정과 후속 작업 판정](<#52-결정과-후속-작업-판정>) 기준 적용함.
4. 회의록에 포함한 정보의 확인 상태와 미결 사항 및 확인 필요 사항의 표시가 일치하는지 확인함. 교정과 요약 과정의 누락 및 확인 상태 변경 여부 점검함.

### 6.1.2 확인 방법과 검증 범위

| 확인 방법 | 확인 대상과 범위 |
|---|---|
| TXT 간 대조 | 두 TXT의 기록 내용과 차이를 확인함. STT 결과를 포함한 두 TXT의 일치만으로 실제 발언의 정확성을 확정하지 않음 |
| 음성 확인 | 음성 자료가 있으면 중요한 불일치와 의미에 영향을 주는 교정을 해당 음성 구간에서 확인함. 실제 확인한 시각 범위와 결과 기록함 |
| 참석자 확인 | 확인자, 확인일, 대상 내용과 설명의 근거를 기록함. 참석자의 사후 설명을 녹음된 발언과 동일하게 취급하지 않음 |

- 검증 기록에는 실제 사용한 방법과 자료, 대상 범위, 확인 결과, 확인자와 일자 및 남은 한계를 구분함. 확인하지 않은 방법이나 구간을 검증 완료로 기록하지 않음.
- 음성 자료가 없거나 필요한 구간을 확인할 수 없으면 그 한계를 남기고 해소되지 않은 내용은 `미확인`으로 유지함. 원음 미확인을 TXT 일치나 참석자의 사후 설명만으로 해소한 것으로 기록하지 않음.
- `source_check`는 기존 값을 사용하고 아래 기준으로 기록함. 값만으로 확인 방법과 실제 발언의 정확성이 드러나지 않으므로 사용 자료, 실제 확인 범위와 남은 한계를 본문에 함께 표시함.

| 값 | 기록 기준 |
|---|---|
| `unverified` | 원자료 대조를 수행하지 않은 상태 |
| `partial` | 대조를 일부 수행했으나 대상 범위의 미처리 구간이나 내용 충돌이 남은 상태 |
| `verified` | 명시한 원자료 범위의 대조와 해당 범위의 불일치 해소를 완료한 상태. TXT만 대조했다면 원음 미대조를 함께 표시하며 실제 발언의 정확성이나 내용의 사실성을 보증하지 않음 |
| `not_applicable` | 원자료 대조 대상이 아닌 정보에 사유와 함께 사용함. 자료 미제공이나 대조 불가를 이 값으로 대체하지 않음 |

### 6.1.3 검증 결과와 재확인

- 동일 내용과 동일 원자료에 대해 완료한 검증은 사용 자료의 식별 정보, 확인 방법, 대상 범위와 결과를 기록하여 재사용함. 단순 재표기나 요약만으로 같은 검증을 일괄 반복하지 않음.
- 변경된 항목과 원자료, 미처리 항목은 다시 확인함. 기존 결과의 재사용 범위는 실제로 확인한 방법과 범위로 제한하고, 의미가 바뀐 항목은 연결된 근거와 영향 항목도 점검함.
- 미처리 구간과 확인을 시도했으나 해소하지 못한 항목을 구분함. 완료한 범위와 남은 확인 필요 사항을 기록하며, 검증 절차의 완료를 모든 불확실성의 해소로 표시하지 않음.

## 6.2 파일 반영과 작업 기록

### 6.2.1 회의록 채택

- 채택 권한과 범위는 사용자의 요청으로 정함. 정식 회의록 작성과 반영까지 요청 범위에 포함된 경우 Codex가 [작업 절차: 반영 대상과 상태](<작업 절차.md#51-반영-대상과-상태>)와 아래 기준에 따라 채택과 반영을 처리함. 초안이나 검토안 요청이면 작업 공간에 유지함.
- 채택은 원자료의 처리 및 제외 사유 기록, 회의록 항목의 근거와 판정, 실제 수행한 검증과 남은 한계 표시 및 문서 형식과 연결 점검 결과를 기준으로 판단함. 기존 요청에서 부여된 권한에 별도 승인 절차를 추가하지 않음.
- 검증 절차가 완료되어도 모든 불확실성이 해소된 것은 아님. 미확인 사항이 남은 회의록도 그 한계를 명시하여 채택할 수 있으며, 중요한 미확인 정보의 표기와 사용은 [회의록 작성 규칙: 미결 사항 및 확인 필요 사항](<#523-미결-사항-및-확인-필요-사항>) 기준 적용함.

### 6.2.2 메타데이터와 문서 반영

- 채택한 정식 회의록은 `01_프로젝트/회의 및 검토`에 반영하고 `target_folder` 제거와 `updated` 갱신함. 문서의 채택 상태는 `status`, 실제 원자료 대조 상태는 `source_check`로 구분하여 기록함.
- 버전 번호와 변경 이력 행은 사용자가 명시한 값과 요청만 반영함.
- [작업 절차: 헤더 번호 도구 실행](<작업 절차.md#33-헤더-번호-도구-실행>)에 따라 번호를 적용하고 헤더 계층, 파일 경로, 메타데이터와 문서 연결 검사함.
- 정식 회의록을 색인에 등록하고 실제 변경 작업을 월별 로그에 기록함. 기록 형식은 [문서 형식](<문서 형식.md>), 반영 절차는 [작업 절차](<작업 절차.md>) 준수함.

### 6.2.3 검증 자료 보관과 관리

- 원본 TXT, 녹취록 완성본과 대조표는 작업 완료 후에도 [회의록 작성 규칙: 저장 경로와 문서 종류](<#22-저장-경로와-문서-종류>)에 지정한 작업 공간 위치에 보존함. 원본의 내용과 원문 위치 기준은 앞 장의 보존 규칙 유지함.
- 자료의 보관 책임은 사용자 또는 사용자가 지정한 자료 관리자에게 있음. 수정과 이동을 수행한 담당자는 자료 정보와 연결을 갱신하고 실제 수행한 변경과 확인 결과 기록함. Codex의 관리 작업도 사용자가 부여한 범위에서 수행함.
- 자료 이동이나 이름 변경 시 정식 회의록과 작업 자료의 파일 링크, 보관 위치, 원자료 식별 정보와 대응 관계를 갱신하고 실제 연결 확인함. 원본을 수정하거나 검증 범위를 넓힌 것으로 기록하지 않음.
