# 1 적용 범위

## 1.1 적용 대상

- 위키의 설명 문서와 리소스 설명 문서에 적용.
- 문체와 기호 사용 규칙은 제목, 본문, 표, 설명 문구 등 직접 작성하는 일반 서술에 적용.

## 1.2 원형 보존

- 원문 인용, 코드, URL, 파일 경로, 수식, 고유 명칭은 정확성을 위해 원형 보존.
- 원문을 바꾸어 요약한 경우 인용이 아닌 요약으로 표시하고 본 규칙 적용.

## 1.3 적용 규정

- 문서 종류별 형식은 [문서 형식](<문서 형식.md>) 준수.
- 사용자가 특정 문서의 표현과 구성을 지정한 경우 해당 요청 적용.

# 2 작성 순서

- 내용을 분류하고 구조를 설계한 뒤 본문 작성. 분류와 구조 설계 없이 단순 문장을 나열하는 방식 금지.
- 원자료의 분류나 구조를 새로 도출할 때의 `구조 우선`은 원자료 추출, 구조 설계, 산문 작성 순서를 의미함.
- 본 절은 [작성 규칙: 서술 방식](<#3-서술-방식>)과 [작성 규칙: 정보 배열](<#4-정보-배열>)을 함께 적용함.

## 2.1 목적 설정과 자료 확인

1. 문서의 목적, 독자, 범위 설정.
2. 정보 수집과 출처 확인.

## 2.2 원자료 추출

### 2.2.1 적용 조건과 최초 추출

- 원자료에서 개수, 분류, 단계나 목차를 새로 도출하는 분석에 적용함.
- 분석 범위의 시작과 끝, 분절 기준을 기록한 뒤 해당 범위를 끝까지 읽음.
- 목차, 항목 수, 단계 수와 분류명을 정하기 전에 원문에서 주체, 행동, 상태와 관계가 바뀌는 근거 단위를 위치 정보와 함께 개수 제한 없이 추출함.
- 최초 추출표를 저장한 뒤 [작성 규칙: 정보 분류, 구조 설계와 검토](<#23-정보-분류-구조-설계와-검토>)에 따라 구조 설계함.

### 2.2.2 추출 단위 식별과 변경

- 추출 단위마다 임시 ID(Identifier, 식별자)와 원문 위치를 붙임.
- 새 근거를 찾으면 기존 ID를 덮어쓰지 않고 추가하거나 분할 이력을 남김.
- 추출 단위를 합치거나 나눌 때 대응표와 이유를 남김. 다른 묶음도 가능하면 유일한 구조로 단정하지 않음.

### 2.2.3 원문 대응과 개수 구분

- 원문에 없는 항목은 `설계 추가`, 사용하지 않는 원문 단위는 `제외`와 사유를 표시함.
- 모든 원문 단위는 새 구조에 한 번 이상 대응하거나 제외 사유를 가짐.
- 원문 단위 수, 분석 묶음 수와 플레이 단계 수를 같은 값으로 간주하지 않고 각각 구분하여 판단함.

## 2.3 정보 분류, 구조 설계와 검토

3. 주제, 기능, 단계 등 적절한 기준으로 정보 분류.
4. 분류한 정보의 관계 정리와 제목 계층 구성.
5. 이해에 필요한 설명 순서 결정 후 작성.
6. 중복, 누락, 근거와 표현의 일치 여부 검토.

# 3 서술 방식

- 짧고 명확한 문장 사용.
- 동일한 계층의 항목은 표현과 상세 수준 통일.
- 문서 내 같은 개념에는 같은 용어 사용. 약어는 처음 사용할 때 전체 명칭 설명.

## 3.1 두괄식

- 문서, 절, 문단, 항목의 결론이나 핵심 우선 제시.
- 근거, 이유, 예시, 부연 설명은 핵심 뒤에 배치.
- 핵심의 의미를 제한하는 조건과 적용 범위는 핵심 문장에 함께 표시.

## 3.2 개조식

- 개조식을 기본 문체로 사용.

### 3.2.1 간결성과 종결

- **간결성**: 불필요한 조사, 접속사, 형용사 등을 최대한 배제하고 핵심 키워드 중심으로 서술.
- **명사형 종결**: 개조식 문장의 끝을 `~음`, `~임`, `~함` 또는 명사 자체로 종결.
- 한 항목에는 하나의 핵심 내용 또는 밀접하게 연결된 내용 배치.

### 3.2.2 항목 계층과 그룹화

- **구조화**: 글머리 기호와 숫자로 항목 계층화. Markdown에서는 불릿 목록(`-`)과 번호 목록(`1.`, `2.`, `3.`) 사용.
- 하위 항목은 들여쓰기로 구분.
- **그룹화**: 같은 헤더 아래 동일 계층의 나열 항목이 6개 이상이면 의미에 따라 그룹화하고 각 그룹에 헤더 추가. 그룹별 동일 계층의 나열 항목은 5개 이하로 구성.
- 그룹 기준은 주제, 기능, 단계 등 내용의 의미에 따라 작성자와 Codex가 검토.
- 추가 헤더는 기존 헤더 계층과 넘버링 규칙 준수.

### 3.2.3 의미 전달

- 의미 전달에 필요한 주체, 조건, 범위, 조사, 상태 표현 유지.
- 키워드 나열만으로 정보의 관계가 불명확해지지 않도록 서술.
- 인과관계나 긴 설명에 문단이 더 적합하면 짧은 문단 사용.

## 3.3 가운뎃점 사용 금지

- 가운뎃점(U+00B7) 사용 금지.
- 항목 나열은 쉼표로 구분하거나 문장 분리.
- 나열하는 항목이 길거나 서로 다른 내용을 담으면 각각의 불릿 항목으로 분리.

## 3.4 슬래시 사용 제한

- 슬래시는 대안이나 동의어를 표시하는 경우에만 사용. 예: `SMS/이메일`, `AI/인공지능`. 예시 약어: SMS(Short Message Service, 문자메시지), AI(Artificial Intelligence, 인공지능).
- 대안이나 동의어가 아닌 항목 나열, 단계 연결, 부연 설명에는 쉼표, 접속 표현, 별도 문장 사용.
- 대안의 선택 조건이 중요하면 슬래시 대신 조건과 선택 관계를 문장으로 명시.
- URL, 파일 경로, 코드, 수식 등은 적용 범위에서 정한 예외 적용.

## 3.5 em dash 사용 금지

- em dash(U+2014) 사용 금지.
- 부연이나 삽입은 쉼표, 콜론, 괄호로 대체하거나 문장 분리.

# 4 정보 배열

## 4.1 배열과 분류

- 핵심을 먼저 제시한 뒤, 이해에 필요한 개요와 정의에서 세부 내용으로 진행.
- 전제와 조건은 해당 내용을 이해하는 데 필요한 위치에 먼저 제시.
- 절차는 수행 순서, 사건은 시간 순서, 비교는 동일한 비교 항목 순서로 정리.
- 같은 분류에 속하는 정보는 함께 배치. 같은 계층에서 서로 다른 분류 기준의 혼용 금지.

## 4.2 표현과 검토

- 병렬 비교는 표, 수행 순서는 번호 목록, 독립적인 항목은 불릿 목록 사용.
- 공통 정보는 한 번 설명하고, 관련 항목에서는 해당 위치 참조.
- 정보 분류와 각 헤더의 상하 관계가 내용상 적절한지는 작성자와 Codex가 검토.
- 번호 계산 도구의 검사 통과를 내용 구조의 검토 완료로 취급 금지.

# 5 근거와 판단의 표시

## 5.1 출처와 참조

- 주요 주장 옆 또는 해당 절에 출처 표시. 문서 끝의 출처 목록만으로 근거를 제시하여 주장과 출처의 관계를 불명확하게 만드는 방식 금지.
- 문서의 특정 절을 참조할 때는 문서명과 헤더 제목 병기. 예: `전투 시스템: 피해 판정`. 절 번호만으로 위치를 가리키는 방식 금지.
- 실제 연결은 대상 파일 경로와 해당 헤더 사용. 파일명과 `title`이 다른 경우에도 표시하는 문서명은 `title` 기준.

## 5.2 주장과 확인 상태

- 원문의 주장과 작성자의 해석 구분.
- 출처에서 직접 확인되지 않는 추론은 `해석` 또는 `추론`으로 명시.
- 확인되지 않은 내용은 `미확인`, 설계가 결정되지 않은 내용은 `미정`으로 표시.
- 상충하는 자료는 차이와 확인 범위 기록. 근거 없이 하나를 확정하는 행위 금지.
- 수치, 날짜, 단위, 적용 조건은 원자료와 대조.

# 6 최종 정리

## 6.1 내용과 문체

- 문서 목적과 무관한 내용 제거.
- 현재 내용과 미정 사항 구분. 대체되거나 폐기된 이전안은 상태 명시.
- 결론과 핵심의 우선 제시 여부, 항목별 의미와 관계의 명확성 확인.
- 개조식 문장의 명사형 종결, 항목 계층, 6개 이상 항목의 헤더 그룹화 여부 확인.
- 일반 서술의 금지 기호 사용 여부와 슬래시의 허용 용도 준수 여부 확인.

## 6.2 형식과 작업 기록

- 원문 인용과 기술 표기의 원형 보존 여부 확인.
- 프론트매터와 본문의 상태 일치 여부 확인.
- 본문 헤더 번호는 [문서 형식: 헤더 넘버링](<문서 형식.md#3-헤더-넘버링>)에 따라 자동 계산과 검증. 기획서의 첫 문서 정보 절과 하위 헤더, 월별 로그는 규정된 범위에서 번호 적용 제외.
- 변경 후 작업 기록은 [작업 절차: 월별 로그](<작업 절차.md#6-월별-로그>)에 따라 작성.
