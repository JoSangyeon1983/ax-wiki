> `06_클라이언트 데이터/`의 한국어를 영어로 옮길 때 따르는 규칙과 검수 절차임.

# 1. 대상과 절차

## 1.1 검수 대상 파일

| 파일 | 담는 것 |
|---|---|
| `06_클라이언트 데이터/공통/localization.json` | 화면에 나오는 모든 UI 텍스트. 평평한 키와 값 맵 |
| `06_클라이언트 데이터/유람기/character_name_pool.json` | 유람기 주인공 이름 풀 |

파일의 용도와 스키마는 `06_클라이언트 데이터/README.md`가 안내함.

## 1.2 검수 방향과 기준

- **방향**: 한국어(`ko`) 원문을 기준으로 영어(`en`)를 봄. 반대 방향이 아님
- **보는 것**: 의미 일치(오역, 누락, 뜻 밀림), 용어 일관성, 표기 규범, 화면에 맞는가

## 1.3 반영 절차

**JSON은 사용자가 직접 관리함.** 에이전트가 값을 고쳐 넣지 않음.

1. 검수 결과를 제안으로 정리해 사용자에게 올림
2. 사용자가 항목별로 승인함
3. 승인분만 JSON에 들어감
4. 반영 뒤에도 `_meta` 없는 평평한 맵 구조를 유지함

# 2. 대소문자

키오스크는 공공 전시장에서 처음 보는 사람이 서서 읽는 화면임. 영어가 모어가 아닌 관람객도 읽음. 그래서 **읽기 부담이 가장 낮은 쪽**을 고름.

## 2.1 기본은 문장 케이스

**첫 글자만 대문자로 쓰고 나머지는 소문자로 씀.** 고유명사와 대명사 "I"는 예외임.

- 어절마다 대문자를 쓰는 제목 케이스(Title Case)는 **서술문에 쓰면 어색하고 읽기 느려짐**. 영어에서 제목 케이스는 제목과 짧은 라벨의 표기임
- 구글 머티리얼과 마이크로소프트 플루언트는 버튼과 라벨과 대화상자 제목까지 **UI 전반을 문장 케이스로 통일**함. 무엇이 "제목"인지 화면에서 가리기 어렵다는 것이 이유임 (L4)
- 애플은 버튼과 메뉴에 제목 케이스를 쓰되 본문과 설명에는 문장 케이스를 씀 (L4)

세 지침이 갈리는 것은 버튼과 짧은 라벨뿐이고, **서술문은 셋 다 문장 케이스임.**

## 2.2 예외 둘

| 예외 | 표기 | 이유 |
|---|---|---|
| 버튼 | 전면 대문자 (`NEXT`, `BACK TO START`) | 한두 낱말이라 대문자로 인한 읽기 손실이 작고, 누르는 것임을 형태로 알림. 현행 표기를 유지함 |
| 판정 등급 | 전면 대문자 (`X`, `OK`, `GOOD`, `PERFECT`) | 리듬 게임 판정 표기 관례이고 탈춤 기획서 등급 표기와 맞물림 |

**긴 문장에는 전면 대문자를 쓰지 않음.** 낱말 윤곽이 사라져 멀리서 읽기 어려워짐. 공공 디스플레이 가독성 지침이 전면 대문자를 피하라고 하는 이유임 (L4).

## 2.3 대문자를 지키는 고유명사

Park Cheomji, Malttugi, Kkeoksoe, Saennim, Chwibari, Deolmi, Deotboegi, Pungmul, AI, QR, E-Book.

배역 이름은 표준 로마자 표기를 따름.

# 3. 문자와 부호

- **아포스트로피는 곧은 표준 문자(`'`)로 통일함.** 곱슬표(`’`)를 쓰지 않음. 키오스크 폰트에서 곱슬표가 깨질 위험을 피함
- **어절 사이 공백 두 칸은 줄바꿈 의도임.** 오류가 아니므로 건드리지 않음. 대소문자를 고칠 때도 공백은 그대로 둠

# 4. 낱말 고르기

## 4.1 한 개념에 한 낱말

같은 한국어를 화면마다 다른 영어로 옮기지 않음. 콘텐츠 이름은 특히 그러함.

- **유람기**: 콘텐츠 이름은 하나로 통일함. `Story`와 `E-Book`과 `Travelogue`가 섞여 있으면 안 됨. `E-Book`은 산출물인 전자책을 가리킬 때만 씀
- 같은 한국어 대사가 두 콘텐츠에 나오면 영어도 같아야 함

## 4.2 전통 어휘는 음역

"얼쑤", "덩실덩실" 같은 전통 감탄사와 의태어는 뜻을 옮기지 않고 소리를 적음(`Eolssu!`, `Deongsil-Deongsil!`). 한 파일 안에서 어떤 것은 음역하고 어떤 것은 번역하는 혼용을 만들지 않음.

## 4.3 이름 풀은 창작 영문명

`character_name_pool.json`의 영어 이름은 로마자 음역이 아니라 **뜻을 살린 창작 영문명**임(김두리 → Merry Rowan, 한재담 → Tale Weaver). 영어권 관람객을 위한 의도이므로 음역으로 바꾸지 않음.

- **겹치는 낱말을 피함**: 서로 다른 이름에 같은 낱말이 들어가면 무작위로 뽑힐 때 겹쳐 보임

## 4.4 원문에 없는 말을 더하지 않음

한국어에 없는 고유명사나 설명을 영어에 넣지 않음. 뜻이 넓어지거나 강조점이 옮겨 가는 것도 밀림임.

- 기다림을 말하는 문장을 생성을 말하는 문장으로 바꾸지 않음
- 다독이는 말("괜찮네")을 칭찬("That's Good.")으로 올리지 않음
