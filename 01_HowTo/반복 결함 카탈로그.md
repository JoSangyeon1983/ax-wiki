> Claude Code 외부 검토자의 적대 발췌에 [[외부 검수 포커스]]와 함께 첨부하는, 과거에 반복해서 발견된 결함 목록. 동일 패턴 재발을 우선 점검하도록 지시함. 운영 규칙은 **"두 번째 재발 시 등재"**: 일회성 결함이 아니라 패턴화된 것만 수록.

# 1. 분류 코드

- **FACT**: 사실/출처/인용 관련
- **LOGIC**: 논리 비약/추론 관련
- **STRUCT**: 문서 구조/wikilink/MOC 관련
- **CONTENT**: 내용 품질/완전성(설명 부실, 항목 혼동) 관련
- **PROCESS**: 작성/정정/검수 과정 자체의 결함(전수 정정 누락 등)

# 2. [FACT-001] 정량 요건의 충족 범위 오해

- 발견/log: 2026-05-14 (덜미 시범콘텐츠 작업)
- 증상: RFP의 "시나리오 6종 이상" 정량 요건을 1차연도 단독 충족으로 본문에 단정. 실제로는 사업 전체(2년 누적) 목표
- 진단: 정량 요건 인용 시 충족 범위(전체/연차별/누적)를 RFP 원문 맥락 확인 없이 추론
- 권고 점검: 정량 요건 인용 본문이 "범위(전체/연차/누적)"를 명시하는가. 충족 주체(연차별 카운트인지 전체 누적인지)가 RFP 원문과 일치하는가
- 재발 시 첨부 포커스 발췌: P1 (출처 일치), P2 (논리 비약)

# 3. [LOGIC-001] 채록본/구비전승을 "정전 텍스트"로 단정

- 발견/log: 2026-05-15 (덜미 - 나만의 유람기 취사 기준)
- 증상: 꼭두각시놀음처럼 채록본마다 거리/줄거리가 다른 구비전승 인형극을 "정전 플롯이 공유 자산"으로 단정 인용. 실제로는 단일 정전 텍스트 없음
- 진단: 외부 자료에서 작품 자체와 특정 채록본 권리를 구분하지 않음. L4(외부 자료)와 L1(정본)을 혼동
- 권고 점검: 구비전승/채록본 기반 자료를 "정전"으로 단정하지 않는가. 권리 단위(작품 vs 특정 채록본/보존회 연출) 구분 표기 있는가
- 재발 시 첨부 포커스 발췌: P2, P3 (한계 조건 누락)

# 4. [LOGIC-002] 상위개념과 사례를 같은 층위에 평면 나열

- 발견/log: 2026-05-14 (덜미 플롯 소재 4종 평면 나열 → 덜미 단일 구성으로 재정리)
- 증상: 분류 체계상 상위 개념(꼭두각시놀음)과 그 사례(서산 박첨지놀이)를 같은 비교 표에 4행으로 평면 나열. 독자에게 잘못된 계통 관념 전달
- 진단: 비교 표 작성 시 항목들 사이의 부모-자식, 형제 관계 확인 누락
- 권고 점검: 비교 표/리스트의 모든 항목이 같은 계통 층위에 있는가. 부모-자식 관계가 평면으로 섞이지 않는가
- 재발 시 첨부 포커스 발췌: P2 (논리 비약), P5 (구조 일관성)

# 5. [STRUCT-001] 결정 후 stale 표현이 본문 잔류

- 발견/log: 2026-05-15 (덜미 - 나만의 유람기: 덜미 구성 제거 / 콘셉트/결정사항 정정), 2026-05-18 (기획서 §4 라벨 stale 4건)
- 증상: 절을 제거/변경/이름 바꾼 뒤에도 다른 절의 옛 전제, 옛 라벨, 옛 참조가 본문 곳곳에 남음. 예시:
	- 마이그/리네임 후 옛 헤딩 라벨 잔류 (예: §4 헤딩이 "시스템 인벤토리" → "기술 구성"으로 바뀌었으나 본문 참조는 "§4 시스템 인벤토리" 잔류)
	- 절 제거 후 다른 절의 옛 전제 잔류 ("정전 플롯 고정" 등)
- 진단: 결정/구조 변경 시 문서 내 교차 참조 점검 누락. 자동 점검 없음
- 권고 점검: 자동 lint(`scripts/wiki_lint.mjs`)로 §/wikilink stale 자동 탐지. 절/라벨 변경 시 grep으로 본문 잔류 확인
- 재발 시 첨부 포커스 발췌: P2 (문서 간 모순), P5 (위키 정합성)

# 6. [STRUCT-002] 도표/표 항목과 부속 정보 혼재

- 발견/log: 2026-05-18 (기획서 §2.가 공용 기능 도표 정리)
- 증상: 표 한 컬럼에 항목명 + 괄호 안 부연(sub-목록/동작/설명/효과)이 섞여 행마다 다른 성격의 정보가 한 형식에 들어감. 예: "기능" 컬럼에 "세션 라이프사이클 (생성/종료/타이머/...)"처럼 기능명 + sub-목록 혼재
- 진단: 표 컬럼 정의 시 정보 형식 일관성 점검 누락. 행마다 다른 성격의 부속 정보를 같은 컬럼에 욱여넣음
- 권고 점검: 표 컬럼 정의 시 (1) 모든 행이 같은 형식의 정보를 담는가 (2) 부연 정보는 별도 컬럼이 적절한가
- 재발 시 첨부 포커스 발췌: P4 (구조 일관성), P5 (정합성)

# 7. [STRUCT-003] 도표/표에 위계 다른 항목 섞임

- 발견/log: 2026-05-18 (기획서 §2.가 세션 컨테이너 분리)
- 증상: 도표/표 안에 의미 위계가 다른 항목이 같은 레벨로 나열됨. 예: 공용 기능 표(Step이 호출하는 횡단 기능)에 "세션 라이프사이클"(Step의 상위 컨테이너)을 같은 행으로 묶음: 위계 반대
- 진단: 표 도입부 정의("Step이 호출하는 횡단 기능")와 실제 행 항목의 위계 점검 누락
- 권고 점검: 표/도표 도입부 정의 ↔ 실제 행 위계 매칭. 의미 위계가 다른 항목은 별도 절 또는 별도 표
- 재발 시 첨부 포커스 발췌: P2 (위계 모순), P5 (구조 일관성)

# 8. [STRUCT-004] 잉여 헤딩 계층 (하위가 1개뿐)

- 발견/log: 2026-05-18 (기획서 §2 시프트: 잉여 H2 계층 제거)
- 증상: 상위 헤딩의 하위가 1개뿐인데 분리. 예: §2 사용자 경험 + §2.가 시스템 플로우 한 H2만 있는 구조 → 잉여 1단
- 진단: 새 절 신설 시 "추후 sibling H2 추가될 가능성"을 가정하나 실제 추가 안 됨. 의도적 분리가 아니라 인공 계층
- 권고 점검: 헤딩 신설 시 (1) 같은 레벨의 sibling이 본 작업에서 1개 이상 존재하는가 (2) 추후 추가 확실한가. 둘 다 No면 한 단계 시프트
- 재발 시 첨부 포커스 발췌: P4 (구조 일관성), P5

# 9. [STRUCT-005] 모듈/프로세스(컴포넌트/흐름) 혼재

- 발견/log: 2026-06-04 (기획서 §4.가 AI 시스템: 진행기/조립이 AI 모듈과 혼재)
- 증상: 한 절/목록에 성격이 다른 항목을 같은 종류처럼 나열. 예: "AI 시스템" 절에 비-AI 오케스트레이션(마당 진행 제어, 결과물 조립)을 AI 모듈과 같은 레벨로 나열 → 독자가 모두 하나의 시스템/같은 종류로 오해. 흐름(§2)이 이미 있는데 컴포넌트 절이 흐름을 또 끌어안기도
- 진단: 항목의 "종류"(컴포넌트 vs 흐름, AI vs 비-AI)를 구분하지 않고 평면 나열. 단수 절 제목("AI 시스템")이 이질 항목을 한 덩어리로 봉합
- 권고 점검: 한 묶음의 모든 항목이 같은 종류인가. 비-AI/오케스트레이션/흐름 항목이 "시스템/모듈" 절에 섞이지 않았는가. 흐름은 흐름 절로, 컴포넌트는 컴포넌트 절로 분리됐는가
- 재발 시 첨부 포커스 발췌: P2 (위계/종류 모순), P5 (구조 일관성)

# 10. [STRUCT-006] 개요-상세 순서 역전

- 발견/log: 2026-06-04 (기획서 §3.마: 캐릭터 레퍼런스 원칙(한 분류 상세)이 자산 목록(전체 개요)보다 앞)
- 증상: 전체 개요/목록보다 한 분류의 상세가 먼저 옴. 독자가 전체 그림을 보기 전에 일부 상세부터 읽음. 또 독립 절이던 하위 내용(메커니즘 비교)이 상위 항목의 하위로 들어가야 하는데 평행 절로 남음
- 진단: 절 순서를 개요→상세(상위→하위)로 정렬하지 않음. 특히 볼드 라벨 → 헤더 승격 시 순서 검토 누락
- 권고 점검: 개요(전체 목록/표)가 상세(분류별 원칙/하위)보다 앞에 오는가. 한 분류 전용 하위 내용이 독립 절이 아니라 그 분류 절의 하위 블록인가
- 재발 시 첨부 포커스 발췌: P5 (구조 일관성)

# 11. [CONTENT-001] 동일 형식/이름을 동일 항목으로 혼동

- 발견/log: 2026-06-04 (기획서 §3.마: 마당 사건 풀 vs 마당 플롯 풀이 같은 텍스트/JSON이라 구별 안 됨)
- 증상: 저장 형식·이름이 닮은 두 항목이 표/목록에서 구별 안 돼 같은 것으로 읽힘. 실제로는 역할이 다름(재료 vs 완제품, 입력 vs 출력)
- 진단: 항목 간 관계(상하/입출력/재료-제품)를 명시하지 않고 형식만 적음. "형식 같음 = 같은 항목" 오해 유발
- 권고 점검: 형식·이름이 닮은 형제 항목이 역할/관계로 구별되는가. 재료→완제품, 입력→출력 같은 관계가 본문에 드러나는가
- 재발 시 첨부 포커스 발췌: P2 (논리/관계), P5

# 12. [CONTENT-002] 한 줄 라벨로 항목 설명 갈음 (역할/입출력 부재)

- 발견/log: 2026-06-04 (기획서 §3.마 "캐릭터 디자인", §4.가 모듈 한 줄 나열)
- 증상: 항목을 이름 + 한 줄 라벨로만 나열하고 "설명했다"고 종결. 독자가 그게 뭔지, 무엇을 만들/쓰는지 못 뽑음. 표 셀이 동어반복("양식 가이드: 양식 문서/예시")
- 진단: 항목별 역할/입력/출력/용도를 정하지 않고 표면 문장만 생산. 자기검수가 형식만 보고 내용 완전성을 안 봄
- 권고 점검: 각 항목이 역할 + 입력/출력(또는 용도/산출물)까지 적혔는가. 분류와 산출물이 동어반복 아닌가. "이걸 보고 무엇을 만들/쓸지 알 수 있는가"
- 재발 시 첨부 포커스 발췌: P3 (한계/완전성), P4 (구조)

# 13. [STRUCT-007] 제목+본문 묶음을 헤더 대신 볼드 라벨로 둠 (자기 선택 관대 통과)

- 발견/log: 2026-06-08 (덧뵈기 2장 세션 라이프사이클/세션 데이터/영상 주의, Step 정의/명세/공용을 볼드 라벨에서 H3로 승격)
- 증상: 제목 + 자기 본문(불릿/표)을 가진 묶음을 헤더가 아니라 볼드 라벨로 둠. 문서 아웃라인과 wikilink anchor에서 빠지고, 작성자 자기검수에서 "내가 한 선택"이라 관대하게 통과됨
- 진단: 헤더 vs 볼드 판단을 "병렬 개수" 같은 약한 휴리스틱으로 함. 표준 원칙(제목 + 본문 = 절 = 헤더) 미적용. 기존 구조 선택을 표준으로 재검토하지 않는 자기 관대성
- 권고 점검: (1) 제목 + 본문 묶음이 볼드 라벨로만 돼 있지 않고 헤더로 올라갔는가 (2) 헤더로 못 올리는 제약(H3 넘버링 충돌 등)이면 상위 묶음을 별도 헤더로 분리했는가 (3) 기존 볼드/구조 선택을 "내가 했으니 맞다"로 통과시키지 않고 표준 원칙으로 재검토했는가
- 재발 시 첨부 포커스 발췌: P4 (구조 일관성), P5 (정합성)

# 14. [STRUCT-008] 1단계 불릿에 복수 항목 욱여넣기 / 제목 복수 주제 평면

- 발견/log: 2026-06-16 (플랫폼 사양 §1: 두 주제(적용 범위, RFP 추적)와 독자별 관심 4역할을 평면 불릿로 섞음)
- 증상: 한 1단계 불릿에 서로 구별되는 항목(역할별/단계별/종류별 서술)을 한 줄로 욱여넣음. 또는 헤딩 제목이 복수 주제('A와 B')인데 본문은 평면 불릿로 두 주제를 섞음
- 진단: 불릿 작성 전 "이 묶음에 항목이 몇 개인가, 제목이 몇 주제인가"를 분류하지 않음. 빠른 확인 목적을 한 불릿 압축으로 오해
- 권고 점검: (1) 한 1단계 불릿에 항목 2개 이상이 모이면 sub-bullet나 표 행으로 분리했는가 (2) 제목이 복수 주제면 본문도 소제목으로 나뉘었는가
- 재발 시 첨부 포커스 발췌: P4 (구조 일관성), 가독성 발췌

# 15. [STRUCT-009] 목록 형식 오선택 (표/라벨형/서브/번호 혼동)

	- **지어낸 것을 표기로 통과**: 설계에 빈자리가 보이자 근거를 찾는 대신 창작으로 메우고 "(잠정)", "고증 자문 항목"을 붙여 규칙을 지킨 모양을 만듦(먹중 소지품 흐트러짐 연출, 3단계 진폭의 4단계 장단 이월)
- 진단: 셀프체크가 **출처의 존재**만 물어 발생함. 미승인 문서도 wikilink는 정확히 걸리므로 통과함. [[CONVENTIONS#3.7 외부 근거의 권위 계층]]의 적용 규칙은 L등급 확인을 "검수 발견에서 근거 약함 플래그가 나오면 사용자가" 하도록 두어, **작성자 쪽 사전 관문이 없고 사후이며 사용자 몫**임. 결과물이 자기 정합적이라(인용 정확, anchor 정상, 앞뒤 일치) 자동 lint 0건, 독립 검토도 통과함. 문서 안만 보는 검수로는 원리상 못 잡음
- 권고 점검: (1) 근거로 삼은 문서가 **채택이 끝난 것인가**. `deprecated`는 근거가 못 되고, 채택 여부가 정해지지 않은 초안(각색안, 대안, 검토 중인 설계)도 못 됨. 다만 `status: draft`라는 이유만으로는 배제하지 않음: 이 저장소는 정본 노릇을 하는 문서 다수가 `draft`임 (2) 최신이라는 이유로 현행 정본 취급하지 않았는가. 자매 문서일수록 채택 여부를 확인함 (3) 한 주제의 형제 산출물이 서로 다른 근거에 서 있지 않은가 (4) "(잠정)"과 "고증 자문 항목" 표기가 붙은 항목이 **인용의 불확실성 표시**인가 **창작의 면죄부**인가. 후자면 삭제하고 미결로 남김 (5) 이어받은 문서의 인용문을 원문과 대조했는가. 커밋됐다는 것은 검증됐다는 뜻이 아님. 행 번호를 단 인용은 `scripts/quote_check.mjs`가 기계로 대조함
- 재발 시 첨부 포커스 발췌: 사실/정합 발췌 (P1 출처 일치), P3 (근거 약함)

# 23. [PROCESS-002] 목표 개수 선결정과 원자료 끼워 맞추기

- 발견/log: 2026-08-23 (옴탈잡이 연희본 진행을 게임 단계에 연결하는 과정에서 원문 사건 여섯 단위를 확인하고도 설명 편의를 위해 다섯 단계로 합친 뒤, 다섯 단계가 원전 분석 결과처럼 보고됨)
- 증상: 목차, 단계 수, 분류명이나 결론을 먼저 정하고 원자료 내용을 그 수에 맞춰 합치거나 나눔. 원문 사건 수, 분석 묶음 수와 설계 단계 수가 다른데 하나의 `단계`라는 말로 섞여, 설계 선택이 원문 구조처럼 보임
- 진단: 구조 우선 작성 원칙을 원자료 추출보다 앞에 적용함. 결과 개수가 분석의 출력이 아니라 입력이 되고, 합치거나 제외한 원문 단위와 원문에 없는 설계 추가가 보고에서 사라짐
- 권고 점검:
	1. 목차, 결과 개수와 분류명을 정하기 전에 원문에서 주체, 행동, 상태와 관계가 바뀌는 단위를 위치 정보와 함께 개수 제한 없이 추출했는가
	2. 분석 범위의 시작과 끝, 말과 행동을 나누는 분절 기준, 최초 추출표 고정 시점을 구조화 전에 기록했는가
	3. 원문 단위, 분석 묶음과 설계 단계를 다른 이름으로 구분했는가
	4. 새 근거를 발견했을 때 기존 ID를 덮어쓰지 않고 추가 또는 분할 이력을 남겼는가
	5. 원문 단위를 합치거나 나눈 경우 대응표와 이유가 있는가
	6. 원문에 없는 요소는 `설계 추가`, 사용하지 않은 원문 단위는 `제외`와 사유로 표시했는가
	7. 모든 원문 단위가 대응표에 한 번 이상 나타나거나 제외 사유를 갖는가
	8. 다른 합치기 방식도 가능한데 하나의 단계 수를 원전의 유일한 구조처럼 단정하지 않았는가
- 재발 시 첨부 포커스 발췌: P2 (구조와 추론), P3 (누락과 한계), 가독성 발췌 (원문 단위와 설계 단계 용어 구분)
