# 1 기준과 백업

- 기준 목록은 같은 폴더의 `기준 목록.json`에 기록함. 모든 경로는 전환 전 위키 루트 기준임.
- 원본 파일 290개, 46,438,430바이트를 ZIP으로 보존하고 각 항목의 SHA-256과 크기를 전부 대조함. 코드 1개의 별도 추출과 해시 비교로 복구를 시험함.
- 백업의 최초 위치는 `99_Archive/위키 구조 전환 백업/20261104_164743`임. 보관소 이름 전환 후에는 `99_보관소` 아래 같은 하위 경로에 위치함. 보관소의 파일로 연결하는 링크를 만들지 않음.
- 현재 파일 ZIP 외에 Git 상태, 작업 트리와 스테이지의 binary patch, 추적 목록, HEAD와 참조 및 index 등 상태 사본을 보존함. Git 메타데이터는 현재 저장소에 자동 덮어쓰지 않음.
- Git 조회 중 사용자 전역 ignore 파일의 읽기 권한 경고가 있었음. 실제 존재하는 파일은 Git 분류와 관계없이 전부 백업함. 무시 여부는 조회 가능한 규칙의 판정이며 전역 설정 전수 확인을 의미하지 않음.

# 2 전환 적용과 복구

## 2.1 적용 전

- 파일별 이관 목록의 원본 해시와 현재 파일을 비교함. 바뀐 사용자 파일이 있으면 관련 전환 항목을 다시 준비함.
- 운영 규정, 자료, 색인과 도구를 검증용 위키에서 먼저 확인함. 검증용 사본을 만드는 경로와 백업 경로를 재귀 복제 대상에서 제외함.
- 재귀 이동 대상은 작업 루트 내부인지 절대 경로로 확인함. 기존 활성 폴더는 보관소의 전환 전 폴더로 보존하고 새 구조를 반영함.

## 2.2 오류 발생 시

1. 추가 변경을 멈추고 파일별 이관 목록과 적용 기록으로 영향 파일을 확인함.
2. 전환 후 사용자가 수정한 파일은 별도 위치에 보존함. 기존 파일에 ZIP을 일괄 덮어쓰지 않음.
3. 필요한 원본을 ZIP에서 별도 임시 위치로 추출하고 기준 해시와 비교함.
4. 해당 전환 변경만 원래 위치로 복구하고 문서 연결과 도구를 확인함. Git reset과 일괄 checkout은 사용하지 않음.
5. 복구 대상, 실제 검사와 남은 한계를 실행 계획 및 월별 로그에 기록함.

# 3 백업 보존

- 구조 전환 완료 후에도 ZIP과 기준 목록, 참고 규정 사본과 적용 기록을 보존함.
- 전환 전 폴더의 보관 자료와 현재 운영 자료를 구분함. 보관소 안의 예전 AGENTS.md와 규정은 현재 운영 지침으로 사용하지 않음.
