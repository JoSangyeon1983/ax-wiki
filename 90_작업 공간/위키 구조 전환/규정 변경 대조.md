# 1 전환 판단

- 구조 전환은 사용자 시작 지시에 따라 실행함. 기획 내용의 새로운 채택과 승인 결정은 수행하지 않음.
- 기준 자료는 S1에서 고정한 규정과 도구 11개임. 원문과 해시는 기준 목록에서 확인함.

# 2 운영 규정의 변경

| 대상 | 가져온 내용 | AX 조정 |
|---|---|---|
| AGENTS.md | 역할별 구조, 승인 구분, 근거 채택 절차 | AX 대상 명시, 개발 자료 분류, 연결 용도별 예외 표 추가 |
| 작성 규칙 | 두괄식, 개조식, 원형 보존, 근거 표시 | 명칭과 경로에 최신 체계 적용 |
| 문서 형식 | planning_role, approval_status, related_documents | 원자료 이미지 문법 보존과 검증용 연결의 범위 설명 |
| 작업 절차 | 회사 기획서 위치, 채택과 승인 구분, 산출물 관리 | 최신 공통 절차 적용 |
| 회의록 작성 규칙 | 정식 회의록과 교정 자료의 역할 구분 | 기존 내용 및 원음 미대조 상태 보존 |
| 이미지 생성 규칙 | 통합 기록과 검수 절차 | 재사용 자산 06과 독립 전달용 결과 08의 위치 기준 일치 |
| 번역 검수 규칙 | 이번 적용 없음 | AX 대상 파일이 없으므로 전용 규칙과 파일을 가져오지 않음 |
| 도구와 설정 | 새 경로와 아카이브 제외 | 콘텐츠별 EXE ignore 제외. 기존 Obsidian 설정 보존 |

# 3 문서별 판단

- D14는 코어 시스템과 입력 처리의 상세 초안으로 04에, D15는 콘텐츠 정의와 개발 목적을 작성한 기반 초안으로 03에 배치함. 본문 분할과 통합은 하지 않음.
- D14와 D15의 기존 출처는 채택 범위가 미확인이므로 related_documents로 보존함. 본문의 인용은 이전 초안의 참고 맥락임을 문서 앞에서 명시함. status는 draft, approval_status는 unverified임.
- D16은 기존 작업본과 별개로 현재 정본 하위에 보존함. D17은 사용자가 교체한 본문을 발표 피드백 작업 초안으로 보존함. 별도 전달용 파일이 없으므로 08에는 결과물을 임의 생성하지 않음.
- D11은 프로젝트 회의 기록으로 분류하고 type을 reference로 정비함. 기존 confirmed는 유지하며 원본 식별과 partial 범위를 보완함. 새 발언 대조나 결정 해석은 하지 않음.
- 참고 분석과 플로우는 05, 코드 원본 사본은 01의 개발 자료임. 02에 채택 내용을 자동 생성하지 않음.

# 4 자료 보존과 후속 과제

- E01 중복 TXT 14개도 삭제하지 않고 제공 원본과 등록 사본의 두 역할로 보존함. E02 단독 파일은 제공 원본에 두고 기존 14개 분석 범위에 추가하지 않음.
- E03의 이미지 결손 10개는 현재 사용자 편집본에 표시된 임시 경로와 함께 보존함. 빈 이미지와 추정 대체본은 생성하지 않음.
- 과거 로그와 JSON의 경로는 당시 기록으로 보존함. 이전 작업 스크립트와 숨김 검증 사본은 재실행용 운영 도구가 아니며 새로운 작업의 출처로 사용하지 않음.
- 사용자 지정 원자료 이름은 보존함. 연구개발계획서의 현재 파일명과 title에만 단어 구분 공백을 적용하며 대응표에 이전 이름을 남김.
