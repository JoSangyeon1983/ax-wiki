# 1 목적과 현재 범위

- 사용자가 지정한 Word 기획서 양식을 유지하면서 위키의 MD 본문으로 새 DOCX를 만드는 테스트 절차임. 정식 공통 운영 규정으로 반영한 상태는 아님.
- 첫 적용 대상은 [Cave Action 콘셉트 기획서](<../../03_기반 기획/콘셉트/Cave Action 콘셉트 기획서.md>)임. 프론트매터를 제외하고 본문, 표와 이미지 및 초안과 승인 대기 문구를 유지함.
- 기준 양식의 구체적인 슬롯과 보존 조건은 [Word 기준 양식 분석과 변환 계약](<artifact.md>)에서 확인함. 원본 양식과 MD는 변경하지 않음.
- 현재 지원 범위는 H1~H3, 평면 불릿과 번호 목록, 문단, Markdown 표, 굵게, 인라인 코드와 HTML img임. 다른 구문과 복잡한 문서의 변환은 추가 구현과 검수 필요.
- 최초 적용은 Cave Action이며 같은 양식의 Cave Super Ball 변환에도 적용함. 검증 기록은 `--report-dir`로 작업마다 분리함. 기존 옵션을 생략하면 최초 Cave Action 경로를 유지함.

# 2 실행 환경과 생성

## 2.1 준비

- Python과 Node는 Codex의 `codex-primary-runtime/dependencies`에 포함된 실행 파일을 사용함. 일반 시스템 Python이나 별도 설치 패키지를 사용하지 않음.
- Word의 실제 쪽 나눔과 목차 쪽 번호를 계산하기 위해 설치된 Microsoft Word를 사용함. Word는 숨김 및 읽기 전용으로 열고 변경 사항을 저장하지 않음.
- 기본 DOCX 렌더러는 이 환경에 LibreOffice 실행 파일이 없어 단독 실행 불가. `word_render.ps1`로 PDF를 출력하고 `render_from_pdf.py`에서 패키지 렌더러의 PDF 변환 부분만 연결하여 PNG를 작성함. 관리된 스킬 파일 자체는 수정하지 않음.
- 기존 DOCX를 갱신할 때는 사용자가 직접 편집한 내용과 정본 여부를 먼저 확인함. 생성기는 기존 파일이 있으면 중단하며 확인 후에만 `--overwrite`를 사용함.

## 2.2 첫 생성

위키 루트의 PowerShell에서 실행함. 아래 실행 파일 위치는 이번 환경에서 확인한 경로임.

```powershell
$taskPython = 'C:/Users/cellbig/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
$taskNode = 'C:/Users/cellbig/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe'
$taskDocs = 'C:/Users/cellbig/.codex/plugins/cache/openai-primary-runtime/documents/26.1104.12130/skills/documents'

& $taskNode "$taskDocs/container_tools/mark_artifact_operation_started.mjs" --operation-kind create --expected-output-count 1 --output-format docx
& $taskPython '90_작업 공간/워드문서변환/convert_md.py' --source '03_기반 기획/콘셉트/Cave Action 콘셉트 기획서.md' --output '08_산출물/워드 문서 변환/Cave Action 콘셉트 기획서.docx'
```

- `inspect_reference.py`는 기준 양식의 해시와 패키지 목록 및 스타일 증거를 추출하는 읽기 전용 분석 도구임. 기준 양식을 바꾸면 분석과 전 페이지 시각 검수를 다시 수행하고 계약을 갱신함.
- 표지 제목은 MD 파일명에서 정함. 파일명이 `콘셉트 기획서`로 끝나면 앞부분은 주제, 뒤는 부제로 대응함. 별도 배치가 필요하면 `--cover-title`과 `--cover-subtitle`로 지정함.
- 작성자, 발행일과 버전은 임의 입력하지 않음. 버전 관리 페이지의 빈 행은 의도된 입력란임.

# 3 쪽 번호와 검증

## 3.1 Word 쪽 계산과 목차 캐시 갱신

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '90_작업 공간/워드문서변환/word_render.ps1' -InputDocx '08_산출물/워드 문서 변환/Cave Action 콘셉트 기획서.docx' -OutputPdf '90_작업 공간/워드문서변환/검증/cave_action.pdf' -PagesJson '90_작업 공간/워드문서변환/검증/pages.json'

& $taskPython '90_작업 공간/워드문서변환/convert_md.py' --source '03_기반 기획/콘셉트/Cave Action 콘셉트 기획서.md' --output '08_산출물/워드 문서 변환/Cave Action 콘셉트 기획서.docx' --pages-json '90_작업 공간/워드문서변환/검증/pages.json' --overwrite
```

- 재생성 후 같은 Word 출력 명령을 다시 실행하여 최신 페이지 수와 쪽 번호를 확인함. 쪽 번호가 달라지면 캐시 갱신과 재출력을 반복함.
- Word에서 목차와 필드를 갱신한 화면을 읽기 전용 PDF로 출력함. 실제 페이지 값은 본문 bookmark의 Word Range에서 계산함. 생성 DOCX의 목차 캐시에 값을 반영함. 문서를 열 때 강제로 필드를 갱신하는 설정은 추가하지 않음.
- `word_render.ps1`은 경고 표시를 활성화하여 Word 열기 검사를 수행함. 최초 테스트의 경고 숨김 방식은 열기 경고를 놓칠 수 있어 수정함.

## 3.2 내용과 전 페이지 검수

```powershell
& $taskPython '90_작업 공간/워드문서변환/verify_conversion.py'
& $taskPython '90_작업 공간/워드문서변환/render_from_pdf.py' '08_산출물/워드 문서 변환/Cave Action 콘셉트 기획서.docx' '90_작업 공간/워드문서변환/검증/cave_action.pdf' '90_작업 공간/워드문서변환/검증/새 검수 폴더'
```

- `conversion_report.json`에서 입력 MD와 기준 양식의 해시, 대응한 모든 본문 블록, 표와 이미지 및 추가 또는 수정한 패키지 목록을 확인함.
- `verification.json`에서 원본 보존, 본문 순서와 내용, 표 셀, 이미지 해시와 비율, 목차 bookmark와 실제 쪽 번호 및 preserve-only part 대조 결과를 확인함.
- 새 검수 폴더의 모든 페이지 PNG를 열어 표지, 문서 구조, 번호, 표와 이미지의 크기, 목록, 쪽 나눔과 꼬리말을 확인함. 수정하면 새 검수 폴더에 다시 렌더링함.
- 검수 PDF와 PNG는 내부 검증 자료임. 사용자에게는 요청한 DOCX를 제공함.

# 4 첫 테스트 결과와 관리

- 생성 결과: [Cave Action 콘셉트 기획서 DOCX](<../../08_산출물/워드 문서 변환/Cave Action 콘셉트 기획서.docx>), 11쪽. 표지, 빈 버전 관리 표, 목차와 본문 8쪽으로 구성함.
- 내용 대조: 본문 103개 블록, 제목 26개, 표 4개와 이미지 2개. 목차 15개 항목의 실제 쪽 번호를 대조함.
- 양식 보존: 원본 패키지 27개 중 preserve-only part 21개의 바이트 일치, 기존 numbering 정의와 관계, 구역 2개의 속성 및 SDT 속성 보존을 확인함. 초기 출력에서 추가했던 자동 필드 갱신 설정은 제거하고 settings.xml을 원본과 동일하게 복원함.
- 시각 검수: 기준 4쪽과 최종 11쪽을 모두 열람함. 빈 표지 입력란의 안내문 표시를 제거하고 짧은 목록의 쪽 나눔을 조정함. 최종 검수 이미지는 `검증/fidelity-complete/b_render`에 보관함.
- [Word 변환 산출물 관리](<../../08_산출물/워드 문서 변환/Word 변환 산출물 관리.md>)와 산출물 색인에 실제 파일과 변환 기준을 기록함. 결과는 사용자 검토용이며 원문 승인 상태는 유지함.
- 열기 경고 수정 검증: 외부 관계 0개와 내부 TOC, PAGEREF 및 PAGE 필드만 존재함을 확인함. Word의 경고 표시를 활성화한 열기 검사를 통과했으며 수정 후 11쪽의 모든 픽셀이 기존 시각 검수본과 일치함. 기록은 `검증/field_fix_report.json`과 `검증/field_fix_verification.json`에 보관함.

# 5 Cave Super Ball 적용

- 입력: [Cave Super Ball 기획서 초안](<../../03_기반 기획/콘셉트/Cave Super Ball 콘셉트 기획서.md>). 출력은 현재 파일명과 사용자 지시에 따라 [Cave Super Ball 콘셉트 기획서 DOCX](<../../08_산출물/워드 문서 변환/Cave Super Ball 콘셉트 기획서.docx>)로 작성함. 프론트매터 제외와 원문 초안 및 승인 대기 상태를 유지함.
- 생성 시 `convert_md.py`의 `--report-dir '90_작업 공간/워드문서변환/검증/Cave Super Ball'`을 지정함. `--pages-json`과 `word_render.ps1`의 `-PagesJson`도 같은 폴더의 pages.json을 사용함. 기존 Cave Action DOCX와 검증 기록은 덮어쓰지 않음.
- 검증 시 `verify_conversion.py --report-dir '90_작업 공간/워드문서변환/검증/Cave Super Ball'`을 사용함. 목차 개수는 해당 입력의 제목 1과 제목 2 개수로 대조함.
- 직접 렌더링은 `render_from_pdf.py`에 DOCX, 해당 Word PDF와 새 출력 폴더를 지정함. 패키지 `render_and_diff.py`와 연결할 때는 WORD_QA_PDF 환경 변수에 이번 Word PDF 경로를 지정함. 원본 양식의 PDF는 기존 reference.pdf를 사용함.
- 결과: 10쪽, 본문 72개 블록, 제목 21개, 목차 14개 항목, 표 6개와 이미지 2개 대조 및 최종 10쪽 시각 검수 완료. 경고 표시를 활성화한 Word 열기 검사 통과. 자세한 입력 해시와 검토 결과는 [Cave Super Ball Word 변환 관리](<../../08_산출물/워드 문서 변환/Cave Super Ball Word 변환 관리.md>)에 기록함.
