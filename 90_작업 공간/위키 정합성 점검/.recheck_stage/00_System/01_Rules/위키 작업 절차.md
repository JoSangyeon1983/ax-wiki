# 1 작업 정의

- 요청의 목적, 결과물 종류, 최종 목적 폴더 확인.
- 작성, 수정, 확정과 반영 중 부여된 작업 범위 확인.
- 기존 문서 수정 시 실제 현재 내용 확인, 현재안과 대체되거나 폐기된 안 구분.
- 출처 범위는 루트의 [위키 작업 지침: 영역과 참조 범위](../../AGENTS.md#4-영역과-참조-범위) 준수.

# 2 자료 선정

- 최종 목적 폴더에서 허용하는 출처 선정.
- 색인으로 문서 탐색 후 근거로 사용할 문서의 실제 내용 확인.
- 출처가 없거나 확인이 불가능한 내용은 미확인으로 기록.
- 기존 Article 참조 시 확정 상태와 현재 유효한 내용 확인.
- 클로바 노트 TXT와 수기 녹취록 TXT의 대조, 녹취록 완성본과 회의록 작성은 [회의록 작성 규칙](<회의록 작성 규칙.md>)에 따라 수행함.

# 3 작성과 수정

## 3.1 작업 공간과 초안

- 새 문서 작성, 프로토타입 제작과 실질적인 내용 수정은 `90_Workspace`에서 진행.
- [문서 작성 규칙](<문서 작성 규칙.md>)에 따라 분류와 구조화 후 작성.
- [문서 형식](<문서 형식.md>)에 따라 프론트매터와 본문 구성.
- 기존 확정 문서와 프로토타입의 수정 초안은 원본을 보존한 상태로 작성.
- 제작, 수정, 검증 중인 프로토타입은 `90_Workspace`의 프로토타입별 하위 폴더에서 프로젝트 파일과 설명 문서 함께 관리.

## 3.2 구조와 검증 준비

- 정보 분류와 헤더 계층은 작성자가 먼저 결정. 작성 중 헤더 번호 생략 가능.
- 작성, 수정이나 프로토타입 제작 후 설명 문서에 아래 번호 도구 적용. 검증할 준비가 되면 설명 문서의 상태를 `status: review`로 변경.

## 3.3 헤더 번호 도구 실행

### 3.3.1 실행 환경과 첫 번호 부여

- 실행 파일: `00_System/03_Tools/heading_numbers.py`.
- 실행 환경: Python 3.9 이상. 별도 패키지 설치 없이 실행 가능.
- 아래 명령은 위키 최상위 폴더에서 실행. `문서명.md`는 실제 대상 경로로 대체.
- 첫 번호 부여 시 제목 전체 보존과 번호 적용 대상 헤더의 앞부분 번호 추가.
- Article의 첫 문서 정보 절과 하위 헤더는 [문서 형식: Article 문서 정보의 번호 예외](<문서 형식.md#33-article-문서-정보의-번호-예외>)에 따라 번호 없이 유지. 문서 정보 다음 본문 H1은 `1`부터 시작. 적용 대상은 도구가 문서 위치와 프론트매터로 판정.

```powershell
python 00_System/03_Tools/heading_numbers.py apply "90_Workspace/문서명.md" --input unnumbered
```

### 3.3.2 기존 번호 재계산과 제목 보존

- 이미 번호가 있는 문서의 수정과 재정렬 후 기존 번호 재계산 사용. 제목 앞 숫자 표기는 기존 번호로 취급.

```powershell
python 00_System/03_Tools/heading_numbers.py apply "90_Workspace/문서명.md" --input numbered
```

- `unnumbered`는 처음 번호를 부여할 때만 사용. 이미 번호가 있는 파일에 반복 실행 시 중복 번호 발생 가능.
- 기존 문서에 `2026 계획`처럼 번호와 혼동되는 새 제목 추가 시 `--literal-line 12`처럼 실제 행 번호 지정으로 제목 전체 보존. 해당 옵션은 단일 파일 재계산에서만 사용하고 다음 재계산에서는 제거.
- 기존 Article의 첫 `# 1 문서 정보` 또는 `# 0 문서 정보`는 번호 제거와 본문 번호 재계산 대상으로 처리. 예외 절의 하위 헤더도 기존 번호 제거.

### 3.3.3 적용 후 검사와 실행 범위

- 적용 후 해당 문서의 번호와 헤더 링크 검사.

```powershell
python 00_System/03_Tools/heading_numbers.py check "90_Workspace/문서명.md"
```

- `check`의 경로 생략 시 위키 전체를 읽기 전용으로 검사. `apply`는 명시한 파일만 수정.
- 다른 폴더에서 실행 시 `--root "위키 최상위 폴더 경로"` 추가.

### 3.3.4 오류 처리와 인식 범위

- 적용 중 계층 오류나 변경될 헤더의 링크 오류 발견 시 파일 수정 없이 중단. 작성자 또는 Codex의 계층과 링크 검토 후 재실행.
- 링크 오류는 적용 후 헤더 기준으로 판정. 보고된 새 헤더 제목으로 관련 링크 먼저 수정 후 적용 재실행. 도구의 임의 링크 변경 금지.
- 인식 범위는 독립된 `#` 형식 헤더와 일반적인 인라인 Markdown, Obsidian 헤더 링크. 밑줄형 헤더는 정리 대상으로 보고. 참조식 링크나 별칭만을 이용한 연결 등 추가 문법은 별도 검토.

### 3.3.5 종료 상태와 도구 검증

- 종료 코드: `0`은 통과, `1`은 번호, 계층 또는 링크 검사 오류, `2`는 실행 조건 또는 파일 처리 오류. 월별 로그의 번호 검사 제외는 `SKIP_LOG`로 표시.
- 도구 수정 후 동봉 검증 코드 실행.

```powershell
python 00_System/03_Tools/test_heading_numbers.py
```

# 4 검증

이미지의 생성과 수정은 [이미지 생성 규칙: 최종 이미지와 통합 작업 기록](<이미지 생성 규칙.md#54-최종-이미지와-통합-작업-기록>)에 따라 검수 결과를 통합 기록에 남기고 완료한 중간 자료를 작업별로 보관함. 파일 정리만 수행한 경우 원본 보존과 실제 수행한 검증 범위 기록함.

- 아래 검토 항목의 실제 확인 결과 기록.

## 4.1 공통 검토

### 4.1.1 출처와 내용 상태

- 최종 목적 폴더의 허용 출처 범위 준수 여부 확인.
- 주요 주장과 근거의 대응 여부 확인, 실제 근거 내용 대조.
- 원자료 내용과 해석, 추론, 미확인 사항의 구분 여부 확인.
- 미정, 대체되거나 폐기된 내용과 현재 확정 내용의 혼합 여부 확인.

### 4.1.2 서술과 문서 형식

- 분류, 설명 순서와 용어의 일관성, 누락과 불필요한 중복 여부 확인.
- 프론트매터의 필드와 값, 날짜, 링크와 파일 경로의 정확성 확인.
- 정보 분류와 헤더 계층의 의미는 작성자와 Codex가 검토.
- 본문 헤더의 번호 계산과 형식 검증 도구 통과 여부 확인. Article의 첫 문서 정보 절과 하위 헤더는 번호 없는 표기와 계층, 링크 검사. 월별 로그는 번호 적용에서 제외.
- 특정 절 참조에 문서명과 헤더 제목의 병기 여부 확인.

### 4.1.3 리소스와 재검증

- 리소스 파일의 열기 가능 여부와 요청 내용, 규격의 부합 여부 확인.
- 초안에서 사용한 자료의 요약 재확인에 그치지 않고 중요한 주장과 실제 근거 대조.
- 검증 중 문제 발견 시 수정 부분 재확인. 확인하지 않은 항목의 검증 완료 기록 금지.

## 4.2 프로토타입 실행과 구현 검토

- 실제 실행 여부와 실행한 범위 확인. 실행하지 않은 경우 미실행 사유와 미확인 항목 기록.
- 핵심 동작을 실제 실행 결과와 대조하고 검토한 동작의 범위 기록.
- 입력 근거의 출처와 적용 범위 확인, 입력 근거와 구현의 대응 관계 대조.
- 실행 환경, 필요한 의존성과 설명 문서의 실행 방법 일치 여부 확인.

## 4.3 프로토타입 검증 기록

- 실행과 검증 결과, 남은 한계는 해당 프로젝트의 설명 문서에 기록.
- 확인하지 않은 항목은 미확인 상태로 명시하고 검증 완료로 기록 금지.
- 프로토타입 설명 문서의 실행과 검증 기록을 앞번호 지식 폴더의 근거로 사용하는 역방향 참조 불허.

# 5 확정과 반영

## 5.1 반영 대상과 상태

- Articles, Assets와 Prototypes는 검토를 마치고 확정과 반영이 요청 범위에 포함된 경우 정식 폴더에 반영.
- 사용자가 초안 또는 검토안을 요청한 경우 Workspace에 유지. 별도 승인이 실제로 필요한 경우에만 확인 요청.
- References와 Syntheses도 출처 기록과 형식 점검 후 정식 폴더에 반영. 남은 불확실성 보존.
- 확정한 문서는 `status: confirmed`로 기록. 확정 Article, Asset, Prototype에는 `reviewed`, `review_note` 기록.

## 5.2 이동과 색인

- 초안의 `target_folder` 제거. 문서와 프로젝트 이동 후 링크, 리소스 경로와 실행 경로 점검.
- 기존 문서 갱신 시 `created` 유지, `updated`와 검토 기록 갱신.
- 대체된 내용의 별도 보존 시 `superseded`, 채택하지 않은 작업물은 `rejected`로 표시와 사유 기록.
- 관련 색인에 정식 문서 또는 프로토타입 프로젝트의 설명 문서 링크와 한 줄 설명 추가 또는 수정.
- `99_Archive`로 이동한 자료는 Git 관리 대상에서 제외하고 앞번호 폴더에서 해당 자료로 연결되는 링크 제거. 파일 경로 없는 문서명 링크와 첨부 링크도 확인.

## 5.3 프로토타입 반영

- `90_Workspace`에서 제작하고 검증한 프로토타입은 확정과 반영이 요청 범위에 포함된 경우 `05_Prototypes`의 프로토타입별 하위 폴더에 프로젝트 파일과 설명 문서 함께 반영.
- 반영 전 설명 문서의 `status: confirmed`, `reviewed`, `review_note`와 실제 검토 결과의 일치 확인. `target_folder` 제거 후 정식 색인에 프로젝트 설명 문서 등록.
- 이동 후 상대 경로, 실행 경로, 동봉 리소스의 원본 출처와 내부 링크 점검.

# 6 월별 로그

## 6.1 기록 범위

- 로그 경로: `00_System/02_Logs/YYYY-MM.md`.
- 위키 파일에 실제 변경이 발생한 작업만 월별 로그에 기록.
- 하나의 작업에서 여러 파일을 변경하는 경우 한 항목으로 묶음.
- 로그 기록 자체를 별도 작업으로 재기록 금지.
- 기록 대상 작업 완료 시 작업한 달의 문서에 기록. 해당 월의 문서가 없는 경우 생성.

## 6.2 날짜와 항목 형식

- 월과 기록 시각은 별도 지정이 없는 경우 한국 표준시(Asia/Seoul) 기준.
- 로그 제목은 프론트매터 `title`에서 관리. 각 작업 항목은 1단계 헤더(H1, Heading 1)로 작성.
- 월별 로그의 1~5단계 헤더(H1~H5)는 번호 적용 제외. 각 항목의 날짜, 시각과 작업명이 식별 기준.

## 6.3 삽입과 정렬

- 새 기록은 프론트매터 다음, 기존 기록보다 위에 삽입.
- 새 항목 추가 시 기존 항목의 번호 재부여 금지.
- 항목은 작업 시각의 내림차순 정렬. 같은 날짜에도 최신 시각을 위에 배치.
- 기록 시각은 실제 작업 시각 사용. 시간이 불명확한 경우 날짜만 기록, 임의 시각 생성 금지.

## 6.4 기록 내용과 색인

- 로그에 작업 대상, 수행 내용, 변경 이유, 검증 결과와 현재 상태 기록. 양식은 [문서 형식: System과 Logs](<문서 형식.md#10-system과-logs>) 준수.
- 로그는 운영 이력. 프로젝트 지식의 근거는 실제 정식 출처 문서에서 확인.
- 월별 로그 파일 생성 시 색인에 링크 추가.
