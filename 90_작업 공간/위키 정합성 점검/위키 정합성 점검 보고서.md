# 1 점검 결론과 범위

- 재점검 결론: 이관 경로, 현재 문서의 연결과 메타데이터를 정리함. 원문 자체의 불일치와 향후 기획 및 실행 검토는 위키 이관 오류와 구분함.
- 사용자 확인: 연구개발계획서 5개는 기존 위키에서 HWPX 변환과 원문 대조를 마친 문서임. 이번 재점검에서 HWPX 대조를 반복하지 않음.
- 재점검 대상: 아카이브를 제외한 활성 Markdown 26개, PNG 28개와 코드 사본 17개. 과거 로그 본문은 당시 기록으로 보존하고 현재 링크 검사에서 제외함.
- 최초 점검 이력: 당시 Markdown 18개에서 헤더 번호 오류 119건과 내부 연결 오류 115건을 확인하고 수정함. 이전 남사당놀이 색인도 정리함. 이 수치를 현재 잔여 오류로 해석하지 않음.

## 1.1 최초 점검에서 직접 대조한 원자료

| 원자료 | 확인 범위 | 한계 |
|---|---|---|

| `4.hwpx`의 마일스톤 | 역전 연도, 셀빅의 시범 콘텐츠와 후속 연차 주요 일정 대조 | 원문 오류의 올바른 대체값은 확정 불가함 |

원자료 위치와 파일 해시는 같은 폴더의 `external_sources.json`에 기록함. 수정 전 Markdown 내용과 해시는 `before.json`, 최초 검사 결과는 `inventory_before.json`과 `links_before.json`에 보관함. 코드 사본은 [CaveBall 클라이언트 코드 원자료](<../../01_프로젝트/개발 자료/CaveBall/CaveBall 클라이언트 코드 원자료.md>)에서 확인 가능함.

## 1.2 이번 재점검의 판단 기준

- 기존 위키의 원문 대조 완료와 최초 점검에서 Codex가 직접 일부만 확인한 범위를 구분함. 계획서의 `source_check`와 색인을 사용자 확인에 맞게 정정함.
- 원문에 있는 일정 충돌과 오탈자는 이관 오류로 처리하지 않음. 임의 수정이나 새로운 일정 확정 없이 원문과 주의 사항 보존함.
- 존재를 확인하지 않은 협약 변경본이나 승인된 수정 계획서를 필수 제출 자료처럼 요청한 판단 철회함. 별도 변경본이 존재한다고 단정하지 않음.
- 현재 사용자에게 즉시 요구할 자료 제출이나 결정은 없음. 7월 회의일을 확정해 사용할 때는 원문과 이관본의 날짜 차이를 확인해야 하며, 그전까지 미확인 표기 유지함.

## 2.2 메타데이터와 출처 계층

- References 6개에 `type`, `sources`, `source_check` 보완함. 실제 찾은 HWPX와 녹취 위치를 기록하고 일부 대조 범위와 미확인 사항 명시함.
- `overview`, `project`를 현재 위치와 내용에 맞는 `synthesis`, `article`, `reference`로 정리하고 날짜를 문자열로 통일함. 기존 작성일과 초안 상태 유지함.
- 코드 원자료를 References에 보관하여 Syntheses가 외부 코드를 직접 출처로 삼던 문제와 같은 계층의 분석 문서를 독립 근거로 삼던 문제를 정리함. 관련 해설 링크와 직접 원문 근거를 구분함.
- [Cave Super Ball 개요 근거 추출](<../CaveSuperBall/Cave Super Ball 개요 근거 추출.md>)은 임시 작업 기록으로 명시되어 있어 `type: system`과 `consulted_documents`로 정리함. References의 원자료로 사용하지 않음.
- 이미지 28개를 [이관 이미지 관리 기록](<../../06_자산/이미지/이관 이미지 관리 기록.md>)에 등록함. 생성 출처나 프롬프트를 추정하여 채우지 않음.
- 본문 번호는 지정된 `heading_numbers.py`로 계산하고 관련 링크 갱신함. Article 버전 번호와 버전 이력은 변경하지 않음.
